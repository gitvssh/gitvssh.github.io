OpenAI Jalapeño 첫 실측: 추론 칩은 왜 데이터 이동을 줄였나

이 글에서 얻는 것

OpenAI Jalapeño의 첫 추론 성능 결과를 벤치마크 조건, 데이터 이동 설계, 생산 검증과 연말 배포 경계로 나눠 분석합니다.

AI 추론 칩 소식을 볼 때마다 연산 속도 배수부터 눈에 들어오지만, 실제 응답 지연과 전력 비용을 가르는 지점은 종종 데이터가 기다리는 시간입니다. OpenAI가 2026년 8월 25일 첫 자체 추론 칩 Jalapeño의 첫 실측 결과를 공개하면서도 계산 성능보다 프리필·디코드 사이의 데이터 이동을 전면에 세운 이유죠. 다만 공개된 배수를 바로 도입 판단으로 옮기기 전에, 측정 조건과 연말 배포까지 남은 검증 절차를 나눠 살펴볼 필요가 있습니다.

글·해설: 다메카솔

첫 실측 수치는 조건과 함께 읽어야 합니다

OpenAI는 Broadcom과 함께 칩을 처음 발표한 지 두 달 만에, 공개 추론 벤치마크 InferenceX로 측정한 첫 성능 결과를 내놨습니다. InferenceX는 하드웨어와 소프트웨어 스택 변화를 함께 추적하는 Apache-2.0 공개 연속 벤치마크로, 회사는 세 공개 모델을 상용 비교 시스템과 맞대 처리량·전력·지연을 비교했다고 밝혔습니다.

구분 OpenAI 공개 내용 조건 및 확인 범위
시험 모델·도구 GPT-OSS 120B, DeepSeek R1 670B, Kimi K2.5 1T (InferenceX) 상용 비교 시스템과 처리량·전력·지연 비교
최고 처리량 구간 전력당 AI 작업 1.51.9배, 종단 간 지연 1.73.6배 감소 공시 전력 700W, 시험 중 지속 전력 550W 이하
고상호작용 구간 비교 시스템 대비 성능 2.1~4.1배 향상 특정 입출력 길이·정밀도·소프트웨어 설정 기준

배포 일정·상태 2026년 말 자사 인프라 배포 시작 계획 8월 26일 기준 생산 적격성 평가·소프트웨어 성숙화 진행

발표된 배수는 모두 OpenAI가 자사 비교 조건에서 집계한 수치이며, 특정 입출력 길이와 모델 정밀도, 전력 정규화 방식이 전제된 결과입니다. 동일 하드웨어와 소프트웨어로 독립 운영자가 재현한 외부 검증 결과는 이번 발표 범위에서 빠져 있습니다. 칩 개발 과정에서 AI가 만든 구현이 기존 전문가 구현보다 빨랐다는 보고 역시 전체 모델 평균이 아니라 선택된 GPT-OSS attention·mixture-of-experts 블록에만 해당하는 비교입니다.

한 요청 안에서도 병목의 위치가 바뀝니다

LLM 추론 요청 하나를 처리하는 동안에도 시스템이 바빠지는 자원은 단계마다 달라집니다. 입력 토큰을 한꺼번에 읽는 프리필(prefill) 단계에서는 계산 장치가 바쁘게 돌지만, 답을 한 토큰씩 생성하는 디코드(decode) 단계로 넘어가면 모델 가중치와 KV cache를 불러오는 메모리 대역폭이 발목을 잡거든요. 여기에 코어와 칩 사이에서 모델 상태를 옮기는 대기 시간까지 겹치면 전체 응답이 늦어집니다.

예를 들어 수천 토큰 분량의 코드 맥락을 한 번에 넘기고 단계별 추론 답변을 기다리는 요청을 떠올려 볼까요? 입력을 훑는 순간에는 연산 자원이 몰리다가 답변이 길어질수록 메모리 읽기와 칩 간 통신 대기가 병목으로 바뀝니다. OpenAI는 Jalapeño가 모델 상태와 KV cache를 필요한 로컬 위치에 명시적으로 배치하고, 추론 단계마다 계산·메모리·네트워크 조합을 유연하게 바꿔 이동 거리를 줄이도록 설계됐다고 설명합니다. 한 장치의 최고 연산 수치만 높이기보다 요청 전체가 연결된 시스템 안에 머물러 유휴 자원을 줄이는 방향인 셈입니다.

연말 배포와 실무 확인 과제

작동하는 첫 자체 실리콘과 측정 데이터는 나왔지만, 일반 고객이 지금 구매하거나 API에서 하드웨어를 직접 선택하기보다는 내부 검증 단계에 머물러 있습니다. OpenAI는 2026년 말 자사 인프라 배포 시작을 목표로 두고, 8월 26일 현재 생산 적격성 평가와 소프트웨어 성숙화, 대규모 운영 준비, 추가 모델 검증을 이어가고 있거든요. 기존 NVIDIA 등 파트너 가속기를 전면 교체하기보다 훈련과 추론에 파트너 칩을 폭넓게 유지하면서 자체 실리콘을 워크로드와 경제성에 따라 고르는 추가 선택지로 제시했습니다.

다메카솔의 해석

이번 발표에서 주목할 대목은 단일 칩의 속도 경쟁보다 병목을 통제하는 소유 범위가 넓어졌다는 점입니다. 모델과 커널, 메모리 배치, 네트워크, 랙 운영을 한곳에서 함께 조율할 수 있으면 앞 단계의 개선이 뒷단계의 대기 시간을 줄이는 구조로 이어집니다. 반면 특정 워크로드에 맞춘 수직 통합은 다른 모델이나 도구 체인을 올릴 때마다 새로운 커널과 최적화 작업을 계속 요구하는 부담도 안고 있습니다.

인프라 팀이 후속 공개 자료에서 따져 봐야 할 기준은 네 가지로 정리할 수 있습니다.

  • 외부 동일 조건 재현: 독립 운영자가 InferenceX의 같은 입출력 길이·정밀도·전력 기준으로 검증한 공개 결과
  • 실제 전력과 가동률: 대규모 환경에서의 실제 전력 효율과 가동률, 장애 시 성능 저하 폭
  • 소프트웨어와 모델 확장성: 새 모델 탑재 시간과 장애 복구, 모델 업데이트 속도
  • 가격과 총비용: 파트너 가속기 대비 실제 서비스 단가와 운영 경제성
