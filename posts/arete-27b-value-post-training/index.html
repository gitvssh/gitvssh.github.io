Arete-27B: 후학습으로 답변 관점을 바꾼 실험

이 글에서 얻는 것

Arete-27B의 후학습 실험과 개발사가 만든 평가의 범위를 구분합니다.

공개 가중치 모델의 답변 관점을 후학습만으로 바꿨다면, 그 결과를 어디까지 신뢰하고 서비스에 반영해야 할까요? Nous Research가 공개한 Arete-27B는 기반 모델 Qwen3.8-27B에 구조 변경이나 강화학습을 더하지 않고도 특정 질문군에서 서술 관점이 크게 달라질 수 있음을 보여 줍니다. 다만 개발사 평가에서 점수가 올랐다는 사실과 보편적 중립성을 얻었다는 결론은 나눠서 읽어야 합니다.

글·해설: 다메카솔

처음부터 다시 학습하지 않고 관점만 바꾼 방식

Nous Research는 2026년 11월 6일 공식 저장소를 열어 Arete-27B 가중치와 모델 카드를 공개했습니다. 개발사는 이를 서구적 가치를 강화하는 후학습 실험으로 설명하는데요. 기존 모델을 처음부터 다시 학습하지 않고 이미 학습된 가중치 위에 응답 성향만 덧입힌 방식입니다.

핵심 기법은 Inkling이 생성한 답변 데이터를 활용한 지도 미세조정(SFT)입니다. 원하는 답변 예시를 직접 학습시켜 응답을 조율하기 때문에 강화학습보다 경로가 단순한 편이죠. 모델 카드의 라이선스 표기는 Apache-2.0이며, 공개된 가중치와 배포 조건을 저장소에서 확인할 수 있습니다.

803개 질문 평가의 조건과 바뀐 수치

후학습으로 응답이 얼마나 달라졌는지 확인하려고 개발사는 자체 평가 세트인 Propaganda_Eval을 함께 내놓았습니다. 이 평가는 학습 자료와는 별개로 만든 803개 질문으로 두 가지를 측정합니다. 정해 둔 사실을 답하는지 보는 사실 점수와, 중국 정부의 설명을 모델 자신의 입장으로 채택하는지 따지는 선전성 응답 비율입니다.

채점 단계에서는 모델 편향을 가리기 위해 Grok 4.7이 어떤 모델의 답변인지 모델명을 모른 채 채점하는 블라인드 방식을 택했습니다. 추론(thinking)을 끄고 온도를 0으로 고정한 채 두 모델에 같은 질문을 다섯 번씩 물어본 조건과 결과는 아래 표와 같습니다.

평가 항목 설정 및 비교 결과
비교 대상 원본 Qwen3.8-27B vs 후학습 모델 Arete-27B
평가 데이터 NousResearch/Propaganda_Eval 803개 질문 (학습 자료와 별개)
생성 조건 추론(thinking) 끄기, temperature 0, 출력 상한 32,000토큰, 질문당 5회 반복
채점 주체 Grok 4.7 (모델명을 모른 채 채점)
사실 점수 (5점 만점) 2.32 → 2.98
개발사 정의 선전성 응답 비율 22% → 0.9%

표의 수치를 보면 변화가 꽤 뚜렷한데요, 사실 점수가 오르는 동안 개발사 기준의 선전성 응답 비율이 22%에서 0.9% 수준까지 크게 낮아졌음을 알 수 있습니다. 같은 생성 조건에서 반복 측정해 출력 변동성을 억제한 결과인 만큼, 지도 미세조정만으로도 특정 주제에 대한 응답 경향을 크게 바꿀 수 있다는 점은 분명해 보입니다.

개발사 평가 개선과 보편적 중립성의 경계

여기서 한 걸음 물러나 짚어야 할 지점은, 학습 목표를 정한 주체와 평가 기준을 만든 주체가 모두 같은 개발사라는 사실입니다. 질문 세트와 채점 기준, 코드를 공개한 덕분에 외부 검증을 시작할 출발점은 마련되었지만, 공개 자체가 독립 검증을 뜻하지는 않습니다. 또한 이번 측정은 개발사가 정한 803개 질문에 초점을 맞추었기에, 모든 정치적 편향이나 실제 사용자 질문 전반을 대표하는 결과로 보기는 어렵습니다.

예를 들어 사내 리서치 도구나 글로벌 질의응답 서비스에 공개 모델을 붙이는 상황을 떠올려 볼까요? 사용자가 역사적 사건이나 국제 정세처럼 시각이 엇갈리는 질문을 던졌을 때, 서비스 목적에 따라 기대하는 응답 기준은 제각각입니다. 한쪽 서사를 덜 채택하도록 다듬은 모델이라도 실제 운영 환경에서는 다른 논쟁적 주제에서 어조가 쏠리거나 민감한 질문을 과도하게 피할 수 있거든요.

다메카솔의 해석

Arete-27B 사례가 실무 개발자에게 보여 주는 핵심은 공개 가중치 모델에 SFT를 적용해 응답 성향을 조정할 수 있다는 가능성입니다. 그렇지만 개발사 평가에서 점수가 올랐다고 해서 바뀐 관점이 모든 사용자에게 더 적절하다고 결론짓기는 어렵습니다. 도입을 검토하는 팀이라면 자체 업무 질문 세트로 원본 모델과 나란히 두고 아래 세 가지를 먼저 점검해 보는 편이 좋습니다.

  • 사실 누락 여부: 특정 관점의 답변을 피하도록 학습하는 과정에서 필요한 배경 사실까지 빠지지 않는지 확인합니다.
  • 거절 패턴 변화: 민감한 키워드가 들어간 정상적인 요약·분석 요청까지 과도하게 거절하지 않는지 살핍니다.
  • 답변 관점과 일관성: 서비스가 지향하는 기준과 어조에 맞는지, 같은 프롬프트에 대한 응답을 원본 모델과 직접 대조합니다.

결국 후학습으로 답변 관점을 바꾸는 시도는 한결 가벼워졌지만, 그 관점이 우리 서비스에 맞는지 판단하는 몫은 여전히 도입 팀에 남아 있습니다. 가중치와 평가 자료가 모두 열려 있는 만큼, 작은 내부 검증 세트부터 돌려 보며 변화의 득실을 확인하는 일이 가장 안전한 첫걸음인 셈이죠.
