AI가 p값을 계산해도 통계 결론을 틀릴 수 있는 이유

이 글에서 얻는 것

Fisher-R1과 P-Bench가 AI 통계 에이전트의 방법 선택, p값, 결론을 따로 평가하는 방식과 재현성 경계를 살펴봅니다.

AI 에이전트가 분석 코드를 에러 없이 끝까지 돌리고 “귀무가설을 기각한다”는 답까지 내놓았다면 결과를 믿어도 될까요? 실제 과학 데이터 벤치마크 P-Bench의 고난도 과제에서 GPT-5.4는 기각 방향만 맞히면 58.3%를 기록했지만, 기준에 가까운 $p$값까지 함께 요구하자 정답률이 30.5%로 내려갔습니다. 코드가 정상 실행됐다는 사실만으로는 통계적 타당성을 보장하기 어렵다는 뜻이죠.

글·해설: 다메카솔

핵심 내용

  • 실행과 타당성의 분리: 이상치를 보고도 단순 선형 회귀를 고수하면 코드는 잘 돌아가지만, 비모수 검정과는 정반대 결론이 날 수 있습니다.
  • 2단계 검증(P-Bench): 경제·생물·의학 과제 425개에서 방향만 보는 Raw와 $p$값 근접성까지 보는 Strict를 나눠 평가합니다.
  • 학습 성과(Fisher-R1): SFT와 결과 기반 RL을 결합한 Fisher-R1-14B(33.0%)가 고난도 Strict 지표에서 GPT-5.4(30.5%)와 DeepSeek V4 Pro(26.3%)를 앞섰습니다.

코드는 돌아갔지만 검정은 틀릴 수 있다

논문 **「Fisher-R1: Training LLM Agents for Reliable Hypothesis Testing」**은 “AI가 통계 코드를 짤 수 있는가”보다 한 단계 더 까다로운 질문을 던집니다. 데이터 파일과 과학 질문만 받은 에이전트가 분포와 가정을 먼저 살피고, 적절한 검정 방법을 골라 실행한 뒤, 타당한 $p$값과 결론을 내놓을 수 있는지 따져 보는 연구거든요.

예를 들어 저자들이 든 실패 사례에서 에이전트는 데이터에 심한 이상치(outlier)가 있음을 발견하고도 단순 선형 회귀를 그대로 밀고 나갑니다. R 코드는 예외 없이 실행되고 매우 작은 $p$값까지 출력되지만, 이상치 영향을 줄이는 순위 기반 비모수 검정을 적용하면 전혀 다른 결론이 나오죠. 실무에서 데이터 분석 자동화를 구축할 때도 “파일을 읽고 표가 나왔는가”만 확인하면, 선택한 모형이 이상치·이분산성·군집 관측 같은 데이터 구조를 버티는지 점검하는 핵심 단계가 빠지기 쉽습니다.

P-Bench는 실행 흔적과 수치 근거를 함께 본다

이 허점을 검증하기 위해 저자들은 실제 과학 데이터로 P-Bench를 만들었습니다. 에이전트에게는 정답 방법 이름 없이 질문·데이터 설명·CSV 파일만 주어지며, R 환경에서 탐색과 실행을 반복해 선택한 통계 방법, 계산한 $p$값, 기각 여부를 반환해야 합니다. 익숙한 검정 하나만 반복해 점수를 올리지 못하도록 방법 범주를 고르게 분산하고, 깨끗한 환경에서 기준 코드를 재실행한 로그와 전문가 독립 감사로 정답을 검증했습니다.

항목 세부 구성 및 기준
과제 규모 경제학·생물학·의학 실제 데이터 기반 개방형 가설검정 425개 (Easy 203 · Hard 222)
방법 및 함정 17개 통계 방법 범주 (단일 범주 최대 19% 이하), 이상치·이분산성·군집 관측 포함
정답 구축 기준 분석 코드 재실행 로그 연결 + 통계·생물통계 전문가 독립 감사
Raw / Strict Raw는 기각 방향 일치만 확인, Strict는 보고 $p$값이 기준과 양측 $z$점수 0.5 이내인지 추가 검증

Fisher-R1 학습 방식과 벤치마크 결과

단순히 문법만 맞는 코드가 아니라 통계적 근거까지 맞추도록, 연구진은 Qwen2.5-Coder 백본에 지도 미세조정(SFT)과 결과 기반 강화학습(RL)을 차례로 적용한 Fisher-R1을 학습했습니다. 품질 필터를 통과한 합성 분석 궤적으로 기본기를 다진 뒤, 실행 가능성·$p$값 근접성·결론 일관성을 직접 보상으로 삼아 학습시킨 셈이죠.

  • SFT 단계: Qwen2.5-Coder 7B·14B 백본에 합성 과제의 전문가 궤적 4,611개 중 품질 필터를 통과한 3,851개(약 83.5%)를 학습했습니다.
  • RL 단계: 합성 과제 8,642개를 대상으로 코드 실행 가능성, 기준 $p$값 근접성, 결론 일관성을 보상으로 반영했습니다.
평가 지표 및 모델 (3회 독립 실행 평균) Fisher-R1-14B GPT-5.4 DeepSeek V4 Pro 비고
P-Hard Strict pass@1 ($p$값 양측 $z$점수 0.5 이내 + 결론 일치) 33.0% 30.5% 26.3% DeepSeek V4 Pro 대비 단일 시도 평균 상대 21%(최대 26%) 개선
P-Hard Raw pass@1 (기각 방향만 일치) — 58.3% — 방향만 맞춘 비율과 수치 근거까지 맞춘 비율의 격차 확인

Fisher-R1-14B가 고난도 분할에서 비교 모델들을 앞선 점도 인상적이지만, 더 눈여겨볼 대목은 따로 있습니다. GPT-5.4조차 방향만 맞추는 기준과 $p$값 근접성까지 따지는 기준 사이에 두 배 가까운 격차가 벌어졌거든요. 가령 실무 분석에서 에이전트가 우연히 기각 방향만 맞혔더라도 근거 $p$값이 크게 어긋났다면, 의사결정 보고서에서는 그대로 쓰기 어려운 결과입니다.

단일 검정의 경계와 다메카솔의 해석

실제 도입을 검토할 때는 연구의 경계도 함께 짚어야 합니다. P-Bench는 과제당 단일 가설검정만 다루므로 다중비교 보정이나 복합 분석 파이프라인, “어떤 단일 검정도 적절하지 않다”는 판단까지는 평가 대상에서 빠져 있습니다. 또한 논문은 모델을 open-weight로 소개하지만, 2026년 8월 10일 기준 공식 GitHub 저장소에는 README.md만 올라와 있고 가중치·데이터·코드는 비공개 상태라 외부에서 전체 실험을 재현하기는 어렵습니다.

저자들 역시 통계 에이전트가 부실한 주장에 그럴듯한 수치 정당성을 입힐 위험을 경고하며, 인간 통계 검토의 대체물이 아니라 평가·감독 도구로 선을 긋습니다. 따라서 데이터 분석 에이전트를 업무 파이프라인에 넣는다면 “분석 완료”를 단일 상태로 두기보다, 아래 다섯 가지 게이트로 나누어 확인하는 편이 안전합니다.

  1. 실행: 데이터 로드와 R 코드가 예외 없이 끝까지 실행됐는지 확인합니다.
  2. 가정: 선택한 통계 방법이 분포·이상치·이분산성·군집 관측에 부합하는지 점검합니다.
  3. 근거: 보고된 $p$값과 통계량이 실제 실행 로그와 일치하는지 대조합니다.
  4. 결론: 기각 여부가 산출된 수치 근거와 일관되게 연결되는지 검증합니다.
  5. 검토: 방법 선택의 타당성과 해석의 한계를 사람이 최종 승인합니다.
