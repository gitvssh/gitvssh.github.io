이 글에서 얻는 것

AI 에이전트가 내린 의사결정의 근거를 며칠 뒤 추적하려면 왜 텍스트 로그만으로 불가능할까요? 결정론적 연산(derive)과 확률적 LLM 추론(infer)을 분리하고 지식 계보(Lineage)를 영구 자산화하는 의미 지속성(Semantic Persistence) 아키텍처를 분석합니다.

글·해설: 다메카솔

AI 에이전트가 수십 번의 API 도구 호출과 팀원의 중간 승인을 거쳐 복잡한 비즈니스 결정을 내렸습니다.

그런데 일주일 뒤 장애가 발생하거나 감사가 들어와 **“에이전트가 도대체 어떤 문맥(Context)을 보고 왜 이런 결정을 내렸으며, 당시 담당자는 무엇을 승인한 것인가?”**를 역추적하려 할 때, CloudWatch나 데이터독 로그 창을 열어보면 수만 줄의 비구조화된 텍스트 덤프만 남아 있어 아연실색하게 됩니다.

이 문제의 본질은 **“기존 시스템들이 단순히 프로세스를 복구하기 위한 ’실행 지속성(Execution Persistence)’만 저장하고, 결정의 인과관계를 설명하는 ’의미 지속성(Semantic Persistence)’을 저장하지 않았기 때문”**입니다.

최근 발표된 포지션 논문 **「Workflow as Knowledge: Semantic Persistence for LLM-Mediated Workflows」**는 AI 워크플로우를 단순한 일회성 실행 스크립트가 아니라, **“정의, 실행 인스턴스, LLM 판단, 입력 맥락, 승인 이력이 유기적으로 연결된 지식 그래프(Knowledge Graph) 객체로 다루자”**는 매우 깊이 있는 엔지니어링 패러다임을 제안합니다.

실행 지속성 vs 의미 지속성: 왜 로그 덤프만으로 안 되는가?

백엔드 아키텍처 관점에서 두 지속성(Persistence)은 명확히 구분되어야 합니다:

  1. 실행 지속성 (Execution Persistence)
    • 목적: 장애 발생 시 중단된 위치부터 작업을 재개(Resume)하기 위함
    • 데이터: 컨테이너 메모리 덤프, Celery/Airflow 태스크 큐, 단순 체크포인트
  2. 의미 지속성 (Semantic Persistence)
    • 목적: 사후에 **“왜 그런 판단을 내렸고 무엇에 의존했는가?”**를 질의(Query)하고 감사하기 위함
    • 데이터: 판단 시점에 모델이 바라본 입력 스냅샷, 사람 승인 권한, 인과적 의존관계 그래프

핵심 원칙: derive(결정론적 계산)와 infer(확률적 추론)의 엄격한 분리

이 논문에서 제안하는 가장 실용적인 아키텍처 원칙은 워크플로우 내의 모든 액션을 다음 두 가지로 명확히 분리하는 것입니다:

  • derive (결정론적 연산):
    • 정규식 파싱, 스키마 유효성 검증, 단위 테스트, 비즈니스 룰 계산처럼 “동일한 입력에 대해 항상 100% 동일한 결과가 보장되는 순수 함수형 로직”
  • infer (확률적 LLM 추론):
    • 텍스트 요약, 의도 분류, 비정형 데이터 의미 해석처럼 “선언된 맥락 안에서 모델이 확률적으로 생성하는 비결정론적 판단”

워크플로우 엔진은 infer 단계를 호출할 때 당시 주입된 프롬프트와 문서 스냅샷을 1급 지식 객체로 캡슐화하고, 모델이 함부로 외부 시스템 쓰기(Write)를 실행하지 못하도록 샌드박스 정책으로 감싸야 합니다.

워크플로우를 지식 객체로 영구 자산화하는 6대 요소

논문이 제시하는 의미 지속성 모델은 6가지 지식 엔티티를 연결합니다:

  1. 워크플로우 정의 (Definition): 적용된 정책과 버전
  2. 실행 인스턴스 (Instance): 실제 실행 트레이스
  3. 컨텍스트 스냅샷 (Context Snapshot): 판단 당시 모델이 본 정확한 자료
  4. 추론 기록 (Inference Record): LLM의 중간 추론 및 신뢰도
  5. 승인 기록 (Approval Record): 승인권자의 역할 및 허용 범위
  6. 의존관계 (Dependency Lineage): 전제가 바뀌었을 때 재계산해야 할 다운스트림 목록

다메카솔의 해석: 에이전트 시스템을 위한 ‘데이터 리니지(Lineage)’ 설계

시니어 백엔드 및 AI 아키텍트로서 이 논문이 주는 핵심 실무 지침은 명확합니다:

  1. 로그와 의사결정 메타데이터의 분리: 로그 수집기(Stdout)에 모든 것을 흘려보내지 말고, 중요한 비즈니스 의사결정은 이벤트 기반의 구조화된 데이터(JSON Schema/RDBMS)로 영구 저장하세요.
  2. 지식 계보(Lineage) 추적성 확보: “사용자에게 이 가격 할인이 적용된 이유”를 묻는다면, 어떤 LLM 프롬프트 버전과 어떤 데이터 소스에 의해 계산되었는지 1클릭으로 역추적할 수 있는 그래프 인덱스를 구축해야 합니다.
  3. 승인과 숙의의 분리: 단순한 “OK 클릭” 로그만 남기지 말고, 어떤 옵션들 사이에서 고민하고 선택했는지의 근거(Rationale)를 남겨야 조직의 집단 지성이 축적됩니다.
