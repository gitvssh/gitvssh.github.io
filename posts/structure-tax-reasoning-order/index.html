AI의 JSON 답변, 필드 순서까지 시험해야 하는 이유

이 글에서 얻는 것

Structure Tax의 JSON·XML 필드 순서 실험, 과제별 예외와 추출기 버그를 읽고 스키마 변경을 검증하는 방법을 살펴봅니다.

글·해설: 다메카솔

AI 응답을 JSON으로 받을 때는 어떤 항목을 먼저 생성하게 할지도 정확도 검사에 넣는 편이 좋습니다. 결과를 읽는 프로그램에는 같은 키 묶음이지만, 한 토큰씩 답을 만드는 모델에는 생성 순서 자체가 작업 조건이 되기 때문입니다. 「Structure Tax」의 저자들은 이 차이를 실험으로 비교했고, 저는 특정 형식의 우열보다 응답 스키마와 채점 코드를 함께 점검해야 한다는 점에 주목했습니다.

핵심 내용

  • 생성 순서의 영향: 자기회귀 모델은 이미 출력한 답을 뒤의 추론으로 고칠 수 없으므로, JSON/XML에서 답변 필드를 먼저 쓸지 추론 필드를 먼저 쓸지에 따라 정확도가 달라질 수 있습니다.
  • 과제·모델별 차이: GSM8K의 GPT-4o에서는 추론 먼저 JSON(95.60%)이 답변 먼저 JSON(55.34%)보다 크게 높았지만, LogicBench나 Spider의 Llama-3.1-8B처럼 순서나 형식의 유불리가 달라지는 예외도 나타났습니다.
  • 채점·추출기 점검: 부록 A.3에 보고된 Gemma3-4B 자유형 응답 추출기 버그(MMLU 29.8%, LogicBench 45.2% 빈 답 추출)는 모델 출력 품질과 파서·채점기 오류를 분리해 확인해야 함을 보여 줍니다.

같은 JSON 항목인데 무엇이 달라질까

한 토큰씩 앞선 출력을 조건으로 다음 토큰을 생성하는 자기회귀 모델에서는 이미 출력한 답이 뒤에 이어지는 설명을 참고할 수 없습니다. 연구진은 이 특성에 주목해 JSON과 XML 각각에서 답변을 먼저 쓰고 이유를 붙이는 순서와 추론을 먼저 쓴 뒤 답변을 쓰는 순서를 비교하고, 자유형 응답도 함께 평가했습니다.

여기서 말하는 순서는 서버에서 완성된 JSON 객체의 키를 화면 표시용으로 재정렬하는 일이 아니라 모델이 텍스트를 생성하는 순서입니다. 저자들은 프롬프트 지시로 출력 형식을 지정했으므로, 토큰 선택을 강제하는 구조화 출력 API나 내부 추론을 별도로 수행하는 모델에 적용할 때는 그 환경에 맞는 추가 확인이 필요합니다.

어떤 조건에서 차이가 났을까

저자들은 GPT-4o, Gemini-Flash-2.0, Claude-Sonnet-4.5, Llama-3.1-8B, Gemma3-4B 다섯 모델을 수학·지식·논리(답 일치 여부)와 SQL(실행 결과 일치 여부) 네 과제로 평가했습니다. 원문 표 1은 temperature 0에서 5회 실행한 평균과 표준편차(±)를 보고합니다.

과제 (평가 문항 수) 모델 JSON 답변 먼저 JSON 추론 먼저 자유형 출력
GSM8K (1,319개) GPT-4o 55.34±1.58% 95.60±1.01% 88.78±1.02%
LogicBench (500개) Llama-3.1-8B 76.00±1.05% 74.60±2.05% —
Spider 검증 (1,030개) Llama-3.1-8B — 54.84±2.71% 64.99±1.85%

GSM8K 수학 문제에서 GPT-4o는 필드 순서를 바꾸는 것만으로 55.34%에서 95.60%로 큰 차이를 보였습니다. 반면 LogicBench의 Llama-3.1-8B에서는 답변 먼저와 추론 먼저가 비슷했고, SQL을 생성하는 Spider 검증 문제에서는 자유형 출력(64.99%)이 추론 먼저 JSON(54.84%)보다 높았습니다.

따라서 이 결과를 모든 모델과 업무에 똑같이 적용되는 단일 규칙으로 읽기보다, 실제 서비스의 모델과 질문 묶음에서 직접 비교해야 할 실험 변수로 받아들이는 편이 정확합니다. 모델 이름뿐 아니라 출력 형식과 실행 조건을 함께 기록해야 한다는 점은 에이전트 평가의 설정 문제와도 맞닿아 있습니다.

부록의 추출기 버그를 함께 읽어야 하는 이유

부록 A.3에는 Gemma3-4B의 자유형 답변을 읽는 추출기에 버그가 있어, 빈 답으로 추출된 비율이 MMLU에서 29.8%, LogicBench에서 45.2%에 달했다는 점이 명시돼 있습니다. 공개 원문만으로는 이 버그의 수정 전후 결과가 본문 집계에 어떻게 반영됐는지까지 확인되지 않으므로, 해당 모델에서 구조화 출력이 자유형보다 높게 나온 수치를 곧바로 추론 능력 향상으로 단정하기는 어렵습니다.

내부 표현 분석 역시 공개 가중치 모델인 Llama와 Gemma 두 모델에서 수행됐고, 저자들은 더 복잡한 스키마·훈련을 통한 적응·다언어 확장을 후속 과제로 남겼습니다. 본문 표와 부록의 추출기 기록을 나란히 읽으면, 모델이 실제로 무엇을 생성했는지와 평가 코드가 무엇을 읽어 냈는지를 왜 분리해 점검해야 하는지 분명해집니다.

다메카솔의 해석: 스키마 변경도 회귀 검사에 넣기

서비스에서 AI 응답 스키마를 바꾼다면, 기존 요청 묶음을 고정한 뒤 필드 변경 전후의 형식 통과율, 정답률, 추출 실패율을 각각 나누어 기록하는 회귀 검사를 두겠습니다. 실패한 원시 응답을 열어 봤을 때 모델이 계산을 틀렸는지, 파서가 답을 놓쳤는지, 뒤의 추론과 앞의 답이 서로 어긋났는지 구분할 수 있어야 고쳐야 할 지점이 보이기 때문입니다.

사용자 화면에서는 결론을 먼저 보여 주는 편이 읽기 좋을 때가 많습니다. 모델이 생성하는 필드 순서와 화면에 표시하는 순서를 분리하면, 모델에는 추론이 먼저 오도록 생성하게 하면서도 화면에는 결론부터 보여 주는 식으로 두 요구를 함께 만족시킬 수 있습니다.
