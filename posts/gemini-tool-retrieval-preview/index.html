AI 뉴스글·해설: 다메카솔발행 2026년 11월 20일

Gemini 도구 검색: 필요한 매개변수만 불러온다

이 글에서 얻는 것

도구 이름·설명과 매개변수 구조를 나눠 읽는 방식, 프리뷰 지원 범위와 과금 조건을 설명합니다.

글·해설: 다메카솔

Google은 2026년 11월 19일 Gemini API Tool Retrieval을 프리뷰로 공개했습니다. 도구의 이름과 설명은 모델에 먼저 보여 주고, 호출에 필요한 매개변수 구조는 그 도구가 필요해질 때 불러오는 기능입니다. 공식 문서상 Interactions API의 v1beta에서 제공되며 generateContent는 지원하지 않습니다.

이름표와 사용 설명서를 나누는 방식

에이전트에 도구를 붙일 때는 이름뿐 아니라 어떤 값을 넣어야 하는지도 알려 줍니다. 예를 들어 배송 조회 도구라면 주문 번호의 자료형과 필수 여부가 매개변수 스키마에 들어갑니다. 도구가 늘면 이런 상세 정의도 함께 늘어납니다.

Google이 설명한 기본 방식은 요청에 tool_search를 추가하고, 나중에 불러올 도구에 defer_loading: true를 설정하는 것입니다. 모델은 남아 있는 이름과 설명을 보고 도구를 찾습니다. API가 해당 스키마를 불러오면 모델이 인자를 갖춘 함수 호출을 만듭니다. 직접 만든 함수의 실행과 결과 반환은 애플리케이션이 맡습니다. 도구 선언은 요청마다 계속 보내야 합니다. 지연 로딩은 선언을 보내지 않는다는 뜻이 아니라, 모델의 초기 문맥에서 상세 스키마를 늦게 읽힌다는 뜻입니다.

그림의 공구 상자는 이 순서를 보여 주는 비유입니다. 실제로 감추는 것은 도구의 존재나 실행 권한이 아니라 처음 문맥에 넣을 상세 스키마입니다. 도구 이름과 설명이 모호하면 선택의 단서도 흐려집니다. 상세 정보의 양을 줄이는 기능과, 어떤 도구를 골라야 할지 알려 주는 설계는 함께 생각해야 합니다.

지원 범위와 비용에서 확인할 것

발표는 Gemini 3.6 이후와 Gemini 4 계열을 지원 대상으로 설명합니다. 확인 시점의 문서에는 gemini-4-hydrogen, gemini-4-argon, gemini-3.8-flash, gemini-3.6-flash가 구체적으로 열거돼 있습니다. 아직 프리뷰여서 정식 제공 전 API 형태가 바뀔 수 있습니다. 서버 측 검색은 같은 API 요청 안에서 이뤄집니다. 별도 도구 목록이나 사용자별 필터를 직접 관리하는 클라이언트 측 검색도 가능하지만, 이 경우 검색마다 애플리케이션과 한 차례 추가 왕복이 필요합니다.

Google은 도구 검색 자체에 별도 요금을 붙이지 않는다고 설명합니다. 토큰 요금까지 무료라는 뜻은 아닙니다. 검색 기능을 켜는 데 소량의 고정 입력 토큰이 추가되고, 불러온 스키마도 입력으로 과금됩니다. 또한 문서는 서버 측 검색마다 전체 문맥과 새 스키마를 넣은 추가 모델 호출이 발생하며, 그 입력도 과금된다고 명시합니다. 따라서 읽지 않은 스키마가 많다는 이유만으로 절감 폭을 확정할 수는 없습니다. 캐시와 검색 횟수까지 함께 봐야 합니다. 이 글에서 비용이나 응답 시간을 직접 측정하지는 않았습니다.

다메카솔의 해석: 목록 크기와 작업 성공을 같이 보자

이 변화는 도구를 많이 연결할 때 생기는 문맥 부담을 줄이는 선택지입니다. 도입을 검토한다면 같은 요청 묶음으로 기존 방식과 비교해 입력 토큰, 전체 응답 시간, 올바른 도구 선택 여부를 함께 보는 편이 좋겠습니다. 토큰이 줄어도 필요한 도구를 놓친다면 작업의 품질은 달라질 수 있기 때문입니다.

관련해서 필요한 스킬만 노출하는 SkillBrowser 연구는 선택적으로 정보를 보여 주는 다른 접근을 다룹니다. 연구의 평가 결과를 이번 Google 기능의 성능 근거로 옮겨 쓰지는 않습니다.
