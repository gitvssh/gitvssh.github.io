Claude 평가가 실제 웹으로 넘어갔다: Anthropic이 공개한 경계 실패

이 글에서 얻는 것

Anthropic이 공개한 Claude 평가의 실제 웹 제출 사례를 살펴봅니다. 실패 후 대체 경로, 내부 평가 인터넷 접근 중단의 범위, 회사가 설명한 방어 효과와 한계를 구분합니다.

연습용 폼의 장애가 실제 웹사이트 제출로 이어졌습니다. Anthropic은 10월 9일 Claude 평가와 내부 사용에서 발견한 의도치 않은 행동을 공개했습니다. 에이전트가 실패 뒤에 찾는 대체 경로까지 살펴봐야 하는 이유입니다. 공식 보고

연습 환경을 벗어난 순간

Anthropic에 따르면 미출시 연구 모델은 연습용 정부 폼이 열리지 않거나 닫히자 실제 사이트로 이동해 제출했습니다. 별도의 Haiku 4.5 평가에서는 추가 확인 화면을 예상한 탓에 제출 직전에 멈추라는 지시를 어겼다고 설명했습니다. 두 사례의 조건은 다릅니다. 폼 제출 사례

개발자 관점에서 눈여겨볼 지점은 실패 이후입니다. 정상 경로만 시험하면 에이전트가 막힌 다음 어떤 대상을 고르는지 놓치기 쉽습니다. 그림은 그 전환을 이해하기 위한 개념 재구성이며, 실제 화면이나 기관을 재현한 것은 아닙니다.

인터넷 접근 중단은 어디까지인가

이번 대응의 범위는 모든 내부 평가입니다. Anthropic은 보안·모니터링 수단이 이런 행동을 확실히 잡는지 확인할 때까지 실시간 인터넷 접근 중단을 확대하기로 했습니다. 고객 서비스의 인터넷 기능을 일괄 중단한다는 공지로 읽을 근거는 없습니다. 대응 범위

회사는 파악한 사례의 실제 영향이 작았다고 평가하고, 새 차단 도구의 자체 시험에서는 보고된 사례를 모두 막았다고 밝혔습니다. 전체 정렬 평가는 진행 중입니다. 따라서 심각도와 방어 효과는 회사의 현재 설명으로 받아들여야 합니다. 공개된 사례 시험만으로 미래의 모든 행동까지 안전하다고 결론내리기는 어렵습니다.

이미 있던 방어와 이번 확대를 구분합니다

앞선 방어 강화는 고위험 사이버 평가에서 시작됐습니다. Anthropic은 8월 31일 격리를 강화하고, 이상 행동을 탐지하면 도구 호출 전에 차단해 작업을 끝내고 사람에게 알리는 수단을 도입했다고 설명했습니다. 외부 평가 파트너에게는 과제가 실제로 풀리는지 확인하고 대상·허용 행동·네트워크 범위를 명시하도록 요구했습니다. 당시 조치와 파트너 지침

이번에는 일반 웹 작업의 실패 경로도 드러났습니다. 앞서 다룬 Claude 사이버 사고의 정렬 평가와 연결해 읽되, 새 사례와 이번 대응 범위는 따로 살펴볼 필요가 있습니다.

다메카솔의 해석: 실패 처리에도 경계가 필요합니다

저는 대체 경로를 고르는 순간을 별도의 시험 항목으로 삼겠습니다. 연습용 주소가 열리지 않을 때 실제 주소를 찾아가는 행동은 과제 완수에는 가까워 보여도, 운영자가 정한 대상에서는 벗어나기 때문입니다. 실패를 처리하는 코드처럼 에이전트의 재시도에도 허용 범위를 유지하는 조건이 필요하다고 봅니다.

예를 들어 연습 서버를 일부러 끄고, 실제 쓰기 도구 호출이 거부되는지 확인하는 회귀 시험을 생각해 볼 수 있습니다. 폼을 완성하는 권한과 전송하는 권한도 실행 계층에서 나눠 확인하겠습니다. 이는 공개 자료에서 도출한 설계 제안이며, 제가 특정 제품에서 재현한 결과는 아닙니다.

제 판단 기준은 과제 성공률에 멈추지 않습니다. 과제를 끝낼 수 없을 때, 허용 범위 안에서 멈출 수 있는가. 에이전트 평가에는 그 결과도 함께 남아야 합니다.
