AI가 화면을 확대했다고 정말 더 잘 본 걸까

시각 AI의 도구 호출과 반환 관측의 실제 기여를 정책·궤적·한 단계 개입으로 구분한 인과 감사 연구를 살펴봅니다.

화면을 보는 AI가 확대 도구를 열 번 불렀다고 해서 그 열 번이 답을 더 낫게 만들었다는 뜻은 아닙니다. 모델은 이미 마음속으로 정한 답을 내면서 도구 호출만 덧붙일 수도 있고, 반대로 유용한 단서를 찾은 뒤에도 확대를 멈추지 못해 시간과 계산 예산을 소모할 수도 있습니다. 그래서 도구 호출 기록보다 먼저 물어야 할 질문은 돌아온 관측이 실제로 답을 바꿨는가입니다.

2026년 8월 6일 공개된 프리프린트 The Illusion of Visual Tool-Use: A Causal Audit of Thinking with Images는 crop-and-zoom 도구를 쓰는 시각 추론 모델을 이 질문으로 감사합니다. 연구진은 도구 사용 전후의 정확도만 비교하지 않고, 정책·전체 궤적·한 단계 관측에 각각 개입해 도구를 부른 행동 자체의 효과와 시각 증거의 기여를 분리했습니다.

글·해설: 다메카솔

핵심 내용

  • 인과 감사 3단계: 연구진은 도구 사용을 정책 수준(도구 허용 vs 직접 응답), 궤적 수준(호출 모양은 유지하고 엉뚱한 위치의 crop으로 관측 교체), 한 단계 수준(동일 호출·문맥에서 실제 crop과 다른 위치 crop의 정답 확률 변화 차이를 재는 Visual Evidence Gain, VEG)으로 나누어 행동 지름길과 실제 시각 증거의 기여를 분리했습니다.
  • 평균 점수 뒤의 양극화: 6개 공개 시각 도구 모델을 4개 벤치마크에서 비교한 결과, DeepEyes는 정책 효과가 거의 0에 가까웠고 호출의 81%에서 VEG 절댓값이 0.01 미만이었습니다. Mini-o3는 VisualProbe에서 직접 응답보다 21.3%포인트 높았으나 Qwen3-VL-8B는 MME-RealWorld-Lite에서 오히려 3.7%포인트 낮았습니다.
  • 두 가지 대표 실패 모드: 관측을 유효하게 쓴 Calibrated 궤적 비율은 V* 기준 DeepEyes 7.9%, Qwen3-VL-8B 20.9%, Qwen3-VL-4B 24.1%, Mini-o3 45.0%에 그쳤습니다. 첫 호출 전에 이미 결론을 정해 두는 Calling Without Looking(첫 호출 전 사고 블록에서 최종 답에 가까운 결론을 적은 비율 약 58%)과, 단서를 찾고도 좁은 영역을 반복 확대하는 Looking Without Planning(Mini-o3 기준 호출의 38%가 원본 면적 4% 미만 절단)이 성능을 깎았습니다.

도구를 불렀다는 사실과 그 결과를 썼다는 사실은 다르다

시각 도구를 쓰는 모델에는 원래 이미지와 질문만으로 답을 내는 직접 경로, 확대나 자르기를 수행했다는 행동 자체가 답에 주는 지름길, 그리고 도구가 돌려준 새 관측이 답을 바꾸는 증거 경로가 섞여 있습니다.

일반적인 정확도 비교는 이 세 경로를 한꺼번에 묶어 봅니다. 도구를 허용했을 때 점수가 올라가더라도, 그 상승이 확대된 시각 정보 덕분인지, 모델이 도구를 부르는 동안 더 오래 추론했기 때문인지, 아니면 특정 호출 형식이 다음 답을 유도했기 때문인지 알 수 없습니다. 연구진이 제안한 인과 감사는 이 혼합을 풀어내는 절차입니다.

세 수준의 개입으로 두 경로를 가른다

연구진은 세 가지 수준의 개입으로 도구 행동과 관측 증거를 분리합니다.

개입 수준 비교 방식 측정 대상과 한계 접근 요건
정책 수준 (Policy) crop-and-zoom 도구 허용 실행 vs 처음부터 직접 답하게 한 실행 비교 도구를 쓸 수 있게 한 전체 평균 효과를 보여주지만, 행동 지름길과 관측 기여는 구분하지 못함 Black-box 가능
궤적 수준 (Trajectory) 모델이 선택한 호출 모양은 유지하되 모든 반환 관측을 같은 모양의 엉뚱한 위치 crop으로 교체 진짜 시각 증거를 잃었을 때 전체 실행이 무너지는 정도를 보지만, 이상한 관측에 대한 반응·반복 호출·예산 소진도 함께 반영됨 Black-box 가능 (관측 교체 인터페이스 필요)
한 단계 수준 (Step-wise VEG) 같은 호출·직전 문맥에서 실제 crop을 넣었을 때의 답 확률 변화에서 같은 크기의 다른 위치 crop 변화량을 뺌 호출 자체가 만든 지름길을 상쇄하고 관측 내용의 국소 기여(Visual Evidence Gain, VEG)를 추정함 White-box 필요 (정답 토큰 점수 필요)

이 세 측정값은 서로를 대체하는 지표가 아니라 서로 다른 질문에 답하는 도구입니다.

평균 상승 뒤에 반대 방향의 결과가 섞여 있었다

연구진은 공개 시각 도구 모델 6개를 V*, HR-Bench 4K·8K, VisualProbe(Easy·Medium·Hard 합산), MME-RealWorld-Lite에서 비교했습니다.

정책 수준의 정확도 효과는 모델과 벤치마크에 따라 크게 갈렸습니다. DeepEyes는 전반적으로 효과가 거의 0에 가까웠고, Mini-o3는 VisualProbe에서 직접 답하기보다 21.3%포인트 높았지만 Qwen3-VL-8B는 MME-RealWorld-Lite에서 오히려 3.7%포인트 낮았습니다. “시각 도구를 쓰면 성능이 좋아진다”는 한 문장으로 묶기 어려운 결과입니다.

한 단계 분석(VEG) 역시 평균 점수만으로는 보이지 않는 차이를 드러냈습니다. DeepEyes 호출의 81%는 VEG 절댓값이 0.01보다 작았습니다. Mini-o3는 유용한 최고점이 있었지만 기여도가 낮은 수많은 호출에 희석됐고, Qwen3-VL-8B의 기여는 답이 포화되기 전 일부 호출에 집중됐습니다.

보지 않고 호출하거나, 보고도 멈추지 못한다

논문은 도구 사용 궤적을 도구를 부르지 않은 실행과 세 가지 도구 호출 그룹으로 분류합니다.

  • Calling Without Looking: 실제 시각 단서를 쓰지 않는 무의미한 호출입니다. 첫 호출 전 사고 블록에서 이미 최종 답에 가까운 결론을 적은 비율이 약 58%로, Calibrated 그룹(약 28%)보다 두 배 이상 높았습니다.
  • Calibrated: 반환된 관측을 유효하게 사용해 답을 갱신한 궤적입니다. V* 기준 전체에서 차지하는 비율이 DeepEyes 7.9%, Qwen3-VL-8B 20.9%, Qwen3-VL-4B 24.1%, Mini-o3 45.0%에 머물러, 도구를 제대로 쓴 궤적이 자동으로 다수가 되지는 않았습니다.
  • Looking Without Planning: 유용한 관측을 얻은 뒤에도 불필요한 호출을 멈추지 못하는 궤적입니다. Mini-o3의 경우 이 그룹 호출의 38%가 원본 이미지 면적의 4%보다 작은 영역을 잘라냈는데, 정보를 더 넓게 살피는 행위가 아니라 이미 좁아진 곳을 계속 파고드는 행위에 가까웠습니다.

이득은 도구가 제대로 쓰인 일부 궤적에 집중됐다

V*의 네 인터페이스 기반 모델에서는 Calibrated 그룹만 일관되게 양의 정책 효과를 보였으며, 0이 아닌 전체 긍정 효과의 대부분도 이 그룹이 설명했습니다. HR-Bench-4K에서도 같은 정성적 패턴이 나타났습니다. 전체 평균 점수가 좋아 보이더라도 모든 도구 호출이 조금씩 기여한 것이 아니라, 도구가 제대로 쓰인 일부 궤적의 이득이 나머지 비효율을 덮었을 가능성을 점검해야 합니다.

다메카솔의 해석: 호출 수 대신 답의 변화를 기록한다

이 결과를 실무 제품 평가로 옮긴다면 성공 지표를 “도구를 몇 번 썼는가”에서 끝내지 않아야 합니다. 호출 전후의 답 상태, 반환된 관측, 같은 호출에 다른 위치 관측을 넣었을 때의 반사실적 변화, 추가 호출이 새 증거를 더했는지 여부, 그리고 중단 기준 초과 여부를 함께 기록해야 합니다.

외부 API만 쓰는 black-box 서비스라면 우선 도구 허용과 직접 응답을 비교하고, 동일한 호출 자리에 다른 위치의 관측을 넣어 보는 궤적 교란부터 시작할 수 있습니다. 모델 내부의 토큰 점수까지 볼 수 있는 환경이라면 VEG와 같은 한 단계 검사를 추가해 불필요한 반복 호출을 조기에 끊는 기준을 세울 수 있습니다.

실험 범위와 공개 자료의 한계

이번 실험은 공개 모델과 crop-and-zoom 도구에 한정되어 있어 OCR, 영역 분할, 비디오 프레임 선택, 코드 기반 이미지 조작, 외부 검색 도구에서도 같은 실패 비율이 재현된다고 단정할 수는 없습니다. 또한 논문은 최종 결과만 보상하는 강화학습이 이런 습관을 만들 수 있다는 가설을 제시하지만, 보상 신호만 바꾼 통제 학습으로 인과를 확정한 것은 아닙니다. 아울러 2026년 8월 8일 확인한 공식 코드 저장소(0a5a3e3)에는 README와 MIT LICENSE만 올라와 있고 실행 코드·데이터·체크포인트·실험 설정은 아직 공개되지 않았습니다.

다음에 화면 에이전트가 확대나 캡처를 여러 번 호출한다면 호출 횟수보다 한 가지를 먼저 확인해 보시기 바랍니다. 그 관측을 다른 것으로 바꿨을 때 답도 함께 바뀌는가?
