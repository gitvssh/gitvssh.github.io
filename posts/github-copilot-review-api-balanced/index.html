GitHub Copilot 코드 리뷰 API 지원과 Balanced 기본값 전환

이 글에서 얻는 것

GitHub Copilot 코드 리뷰 요청을 REST·GraphQL API로 연결할 수 있습니다. Balanced 기본값의 적용 시점과 명시적으로 선택한 Lite 유지 조건을 구분합니다.

글·해설: 다메카솔

발행·확인: 2026-10-05

배포 전 점검 파이프라인에서 Copilot 코드 리뷰까지 자동으로 호출하려면, 리뷰를 요청하는 API 경로부터 연결해야 합니다. GitHub은 2026년 10월 2일 REST·GraphQL API를 통해 Copilot 코드 리뷰를 요청하고, 요청마다 분석 깊이(effort level)를 지정하는 기능을 Pro·Pro+·Max·Business·Enterprise 요금제에 정식 제공한다고 발표했습니다. (GitHub 공식 발표)

리뷰 요청을 팀 도구에 연결합니다

이번 업데이트로 웹 화면에서 리뷰어를 수동 지정하는 방식 외에, 사내 CI 스크립트나 배포 전 점검 도구에서 REST·GraphQL API로 리뷰를 트리거하고 요청별로 분석 깊이를 고를 수 있는 통로가 열렸습니다. (API 지원 발표)

연동할 때 함께 확인해야 할 설정 조건은 두 가지입니다.

  • 자동 리뷰 활성화와 분석 깊이의 분리: 설정 문서에 따르면 저장소의 자동 리뷰 켜기/끄기와 분석 깊이 설정은 서로 독립적입니다. 자동 리뷰를 꺼 두었더라도 수동이나 API로 요청한 리뷰에는 지정한 분석 깊이가 적용되므로, API 지원 소식만으로 모든 PR에 자동 리뷰가 돌아간다고 오해하지 않아야 합니다. (리뷰 설정 안내)
  • 조직 정책 활성화: 조직을 통해 Copilot 라이선스를 부여받은 경우, 조직 수준의 Copilot 코드 리뷰 정책도 활성화돼 있어야 요청이 정상 동작합니다. (조직 이용 조건)

Balanced 기본값은 이미 9월 28일 바뀌었습니다

공지 게시일은 10월 2일이지만, 기본 분석 깊이(Default)가 Balanced로 전환된 시점은 9월 28일입니다. 기존에 설정에서 Lite를 명시적으로 선택해 둔 저장소나 조직은 그 선택이 그대로 유지됩니다. (적용일과 예외)

GitHub은 Lite를 빠른 기본 검토로, Balanced를 복잡한 로직·보안 관련 코드·서비스 간 변경을 더 깊이 살피는 수준으로 설명합니다. Balanced는 AI 크레딧과 GitHub Actions 실행 시간을 조금 더 소비할 수 있으며, 각 리뷰에 실제로 적용된 분석 깊이는 PR의 리뷰 개요 댓글에 표시됩니다. (분석 깊이와 사용량)

구분 현재 공식 안내
API 요청 REST·GraphQL 지원, 요청별 분석 깊이 선택 가능
Default 설정 9월 28일부터 Balanced 사용 (명시적으로 고른 Lite는 유지)
Max 분석 깊이 설정 문서에 Coming soon으로 표기 (요금제 이름인 Copilot Max와 구분 필요)

표의 마지막 항목처럼 발표문에 등장하는 요금제 이름 Max와 설정 메뉴에 예고된 분석 깊이 Max(Coming soon)는 서로 다른 개념이므로 혼동하지 않아야 합니다. (분석 깊이 선택 메뉴)

다메카솔의 해석: 요청과 완료를 따로 다룹니다

코드 리뷰 요청을 API로 자동화할 때는 리뷰 요청 발송 기록, 도착한 리뷰 결과, 최종 병합 승인 판단을 각각 별도 상태로 관리하는 편이 안전합니다. 네트워크 지연이나 재시도가 발생했을 때 이미 리뷰가 진행 중인 PR에 중복 요청을 보내지 않으려면 이전 요청 상태를 대조할 수 있어야 하기 때문입니다.

또한 분석 깊이를 높였다고 해서 사람의 최종 검토 책임이 사라지는 것은 아닙니다. GitHub 공식 문서 역시 Copilot이 결함을 놓치거나 잘못된 지적을 남길 수 있다고 명시하고 있으므로, 앞서 다룬 PR 리뷰 단계별 지표처럼 AI 리뷰가 도착한 뒤 사람의 검토와 테스트가 어디서 이어지는지 함께 살피면서 작은 저장소부터 적용 범위를 넓혀 가기를 권합니다.
