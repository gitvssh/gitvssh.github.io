실행 스크립트에 새 옵션을 추가했는데도 AI 에이전트가 계속 예전 방식으로 도구를 호출한다면, 원인은 코드가 아니라 `SKILL.md`의 호출 예시일 수 있습니다. 확장자가 Markdown이라 단순 참고 문서로 넘기기 쉽지만, 에이전트에게는 실행 경로를 좌우하는 구성 요소나 다름없거든요. 「On the Maintenance and Co-evolution of Agent Plugins」는 Claude Code 플러그인 마켓플레이스의 변경 이력을 추적해 자연어 지침과 코드가 어떻게 함께 유지보수되는지 살핀 사전공개 연구입니다.

글·해설: 다메카솔

## 스크립트만 고치면 예전 경로가 남는다

![새 스크립트 장치와 맞지 않는 예전 지침 경로를 에이전트 토큰이 따라가는 장면](./page-01.webp)

에이전트 플러그인은 실행 코드만으로 돌아가지 않습니다. `Skill`·`Command`·`Agent` 같은 자연어 지침 파일이 도구를 언제 어떤 인자로 호출할지 정해 주기 때문이죠. 저자들은 이 결합 구조가 한 번 쓰고 방치되는 문서인지, 코드처럼 반복해서 고쳐지는 소프트웨어인지 물었습니다.

예를 들어 분석 스크립트에 `--format json` 플래그를 새로 넣고 `SKILL.md`의 호출 예시를 예전 그대로 두었다고 해 봅시다. 코드 테스트는 통과하더라도 런타임에 지침을 읽는 에이전트는 구식 인자로 도구를 호출하다 오류를 내기 쉽거든요. Markdown이라는 이유로 단순 문서 수정으로 넘기면 실제 동작 변화가 리뷰에서 가려집니다.

## 마켓플레이스 플러그인의 변경 이력을 어떻게 모았을까

![여러 저장소 상자가 두 단계 여과 장치를 지나 지침 리본과 스크립트 기어, 설정 블록으로 정리되는 장면](./page-02.webp)

연구진은 GitHub Code Search에서 `.claude-plugin/marketplace.json` 파일을 찾고, 중복 저장소와 스타 10개 미만 저장소, 로컬 경로가 풀리지 않는 항목을 걸러냈습니다. 이렇게 추린 표본과 활동 추이는 아래 표와 같습니다.

| 항목 | 수집 기준 및 규모 |
| --- | --- |
| 수집·필터 | 2026년 4월 GitHub 검색, 중복·스타 10개 미만·비로컬 경로 제외 |
| 표본 규모 | 저장소 1,926개(마켓플레이스 2,018개), 유효 플러그인 8,351개 (나이 중앙값 80일) |
| 커밋·구성 | 구성요소 포함 커밋 77,773개(작성자 3,948명), SW 엔지니어링 61.3%, 복합 구성 34.4%(`Commands`+`Agents` 최다) |
| 6개월 성장 | 2025년 10월 월 2,923개 → 2026년 3월 25,618개 커밋 (**8.8배** 증가) |

공식 출시 뒤 6개월 사이 활동은 빠르게 불어났지만, 저장소 나이 중앙값은 80일에 머무르는 초기 생태계입니다. 셋 중 하나꼴로 둘 이상의 구성요소를 담은 만큼 저자들은 실제 유지보수 양상을 더 깊이 추적했습니다.

## 문서 커밋으로 적혔지만 실제로는 기능 변경이었다

![평범한 서류로 보이던 지침 조각이 기계에 들어가 출력 경로를 바꾸는 장면](./page-03.webp)

전체 커밋은 Conventional Commits 정규식과 `GPT-5-mini`로 1차 분류한 뒤, `docs`·`ci`·`style` 변경의 실제 diff를 다시 읽어 작업 성격을 재판정했습니다. 표면 라벨과 실제 변화 사이에는 큰 간극이 드러났습니다.

- **2단계 분류**: 전체 77,773개 중 규칙으로 51,141개, `GPT-5-mini`로 26,632개를 먼저 나눴습니다.
- **`docs`의 80% 재분류**: 원래 `docs`였던 8,007개 중 80%가 diff 기준 `feat`·`fix`로 이동해 `docs` 비중이 **10.3% → 1.7%**로 줄었습니다.
- **새 기능 중심 분포**: 재분류 후 `feat` **39.6%**, `chore` **21.0%**였습니다(선행 연구의 전통 오픈소스 `feat` 17.2%와 비교한 수치).
- **AI 공동 작성 하한**: 공동 작성자 표식으로 **34.9%**가 Claude 공동 작성으로 잡혔으며, 미표식 커밋은 빠져 실제 관여 비율의 하한선입니다.

에이전트가 실행 중 읽는 지침을 고치는 일은 설명 문구 손질이 아니라 행동을 바꾸는 기능 수정에 가까웠던 셈이죠.

## 같은 skills 폴더 안에서는 코드와 지침이 같이 움직였다

![스크립트 장치의 입출력 위치가 바뀌자 연결된 지침 리본도 새 위치로 맞춰지는 장면](./page-04.webp)

구성요소 전체를 넓게 보면 모든 파일이 한 덩어리로 움직이지는 않았고, 우연 기대치보다 자주 함께 바뀐 쌍은 `Agents`와 `Commands`(lift **1.40**)였습니다. `Skills`가 다른 구성요소와 자주 묶인 데는 `Skills` 자체의 높은 보급률이 작용했죠.

반면 같은 `skills/` 디렉터리 안에서는 Python·Shell 스크립트와 Markdown이 우연보다 자주 함께 바뀌었습니다. 스크립트와 지침이 이미 함께 수정된 PR 64건을 저자 두 명이 직접 읽어 보니 **50건(78%)**에서 기능적 연결이 확인됐습니다.

이 수치는 이미 동시 변경이 일어난 표본 안에서의 연결 비중이므로, 전체 스크립트 변경 중 지침 수정이 필요한 비율과는 분모가 다릅니다. 사람 판정과 일치도(Cohen의 카파 **0.62**)를 확인한 `GPT-5-mini`로 남은 259건을 분류한 유형은 아래 표로 정리됩니다.

| 공동 변경 유형 | 설명 | 분류 건수 (259건, Table 8) |
| --- | --- | ---: |
| **인터페이스 변경** | 새 플래그·명령어 추가 및 수정 | 87건 |
| **내부 로직 변경** | 출력 형식·검증 규칙 변경 | 68건 |
| **값·버전 동기화** | 모델 이름·환경 변수·버전 일치 | 33건 |
| **저장소 구조 재구성** | 파일 경로·설정 형식 재배치 | 24건 |
| *(비연결)* | 동시 커밋이나 기능 의존성 없음 | 47건 |

## 한 생태계의 초기 스냅샷이라는 경계

![하나의 젊은 플러그인 생태계만 유리 돔 안에서 관찰되고 다른 생태계는 밖에 남은 장면](./page-05.webp)

연구 수치를 다른 환경으로 일반화하기 전에는 세 가지 범위를 함께 봐야 합니다.

1. **짧은 초기 구간**: 2026년 4월 기준 저장소 나이 중앙값이 **80일**이라 장기 유지보수나 생존 패턴으로 단정하기 이릅니다.
2. **단일 플랫폼**: Claude Code 생태계만 조사해 Cursor, Copilot, Gemini, Codex에서도 같은 비율이 나오는지는 별도 검증이 필요합니다.
3. **분류·표식 민감도**: `GPT-5-mini`·Qwen 분류는 모델과 프롬프트에 영향을 받고, 공동 작성자 탐지도 명시적 표식이 남은 커밋만 포착합니다.

## 다메카솔의 해석

![성인형 카솔이 스크립트 장치와 지침 경로가 함께 맞아야 열리는 배포 관문을 가리키는 장면](./page-06.webp)

자연어 지침을 문서 폴더에 있다는 이유만으로 비실행 산출물처럼 다루면, 리뷰와 테스트가 실제 동작 변화의 절반만 보게 됩니다. [워크플로 자체를 판단 근거로 보존해야 한다는 연구](/posts/workflow-as-knowledge/)처럼 지침 파일 역시 실행 경로의 일부로 관리해야 합니다.

논문이 효과를 직접 시험한 처방은 아니지만, 관찰된 결합 패턴을 저장소 운영에 적용한다면 세 가지를 한 묶음으로 점검해 볼 만합니다.

- **PR 짝 검토**: 스크립트 플래그·경로·출력 필드가 바뀌면 연결된 `SKILL.md` 같은 지침도 함께 갱신됐는지 확인합니다.
- **호출 예시 계약 테스트**: 지침의 호출 예시를 가벼운 계약 테스트(contract test)로 실행해 인자와 경로를 검증합니다.
- **단일 정의 생성**: 모델 이름·환경 변수·스키마 값은 한 곳의 설정에서 생성하고, 자연어 리뷰에서는 에이전트 실행 조건의 변화부터 살핍니다.
