AI 에이전트가 R 분석 코드를 끝까지 실행하고 “귀무가설을 기각한다”는 답을 내놓았더라도, 결론 방향만 우연히 맞춘 비율과 기준 분석에 가까운 $p$값까지 정확히 산출한 비율은 크게 달랐습니다. **「Fisher-R1: Training LLM Agents for Reliable Hypothesis Testing」**이 제안한 실제 과학 데이터 벤치마크 `P-Bench`의 어려운 과제(P-Hard)에서 GPT-5.4는 방향만 보는 `Raw pass@1`이 58.3%였지만, $p$값 근접성까지 따지는 `Strict pass@1`은 30.5%로 떨어졌습니다. 코드가 에러 없이 돌아갔다는 사실과 통계적으로 타당한 결론을 냈다는 사실은 전혀 다른 증거입니다.

글·해설: 다메카솔


## 핵심 내용

- **실행 성공과 방법론 타당성의 분리**: 데이터의 이상치를 보고도 선형 회귀를 고수하면 코드는 정상 실행되고 작은 $p$값이 나오지만, 순위 기반 비모수 검정과는 정반대 결론이 날 수 있습니다.
- **P-Bench 2단계 검증**: 경제학·생물학·의학의 개방형 가설검정 425개 과제(Easy 203·Hard 222, 17개 통계 방법 범주)에서 기각 방향만 보는 `Raw`와 기준 $p$값과의 양측 $z$점수 차이 0.5 이내를 함께 요구하는 `Strict`를 분리해 측정합니다.
- **Fisher-R1 학습과 성과**: Qwen2.5-Coder(7B/14B) 백본에 합성 분석 궤적 지도 미세조정(SFT)과 실행 가능성·$p$값 근접성·결론 일관성 보상 강화학습(RL)을 적용해, P-Hard `Strict pass@1`에서 `Fisher-R1-14B`(33.0%)가 GPT-5.4(30.5%)와 DeepSeek V4 Pro(26.3%)를 앞섰습니다.

## 코드는 돌아갔지만 검정은 틀릴 수 있다

![불규칙한 데이터가 실행 기계를 통과한 뒤 잘못된 결론 저울로 향하는 장면](./page-01.webp)

논문이 던지는 질문은 “AI가 통계 코드를 실행할 수 있는가”보다 훨씬 까다롭습니다. 데이터와 과학 질문만 받은 에이전트가 데이터의 분포와 가정을 살펴 적절한 검정 방법을 고르고, 실제로 분석을 실행한 뒤, $p$값과 귀무가설 기각 여부를 타당하게 보고할 수 있는지를 묻기 때문입니다.

저자들이 든 사례에서 에이전트는 데이터의 심한 이상치(outlier)를 발견하고도 단순 선형 회귀를 그대로 밀고 나갑니다. 코드는 예외 없이 돌아가고 매우 작은 $p$값이 출력되지만, 이상치 영향을 줄이는 순위 기반 검정을 적용하면 같은 결론이 나오지 않습니다. 일반 데이터 분석 자동화에서도 파일을 읽고 표를 뽑아냈는지만 확인하면, 정작 선택한 통계 모형이 데이터의 분포와 관측 구조를 견디는지라는 핵심 질문이 빠지게 됩니다.

## P-Bench와 Fisher-R1은 실행 흔적과 수치 근거를 함께 본다

![질문과 데이터, 실행 작업장, 숨겨진 기준 판정을 세 구역으로 나눈 증거 경로](./page-02.webp)

`P-Bench`는 경제학·생물학·의학 실제 데이터에 기반한 개방형 가설검정 과제 425개(Easy 203개, Hard 222개)로 구성되며, 17개 통계 방법 범주 중 어느 하나도 전체의 19%를 넘지 않도록 설계해 익숙한 검정 하나만 반복해서는 높은 점수를 얻을 수 없게 만들었습니다. 에이전트는 정답 방법 없이 과학 질문과 데이터 설명, CSV 파일만 받아 R 환경에서 탐색·실행한 뒤 (1) 선택한 통계 방법, (2) 계산한 $p$값, (3) 귀무가설 기각 여부를 반환합니다(정답은 논문 문장을 그대로 베끼지 않고 깨끗한 환경에서 기준 분석 코드를 재실행한 로그와 전문가 독립 감사로 구축했습니다).

![검증된 분석 흔적이 품질 체를 거쳐 반복 학습과 두 보상 신호로 이어지는 장면](./page-03.webp)

연구진이 제안한 `Fisher-R1`은 Qwen2.5-Coder 7B·14B 백본 위에 두 단계 학습을 거쳤습니다. 먼저 합성 통계 과제에서 전문가 모델이 만든 4,611개 분석 궤적 중 품질 필터를 통과한 3,851개(약 83.5%)로 지도 미세조정(SFT)을 수행하고, 이어 8,642개 합성 과제에서 코드 실행 가능성·$p$값의 기준 근접성·결론의 일관성을 보상으로 강화학습(RL)을 적용했습니다.

| 평가 지표 및 모델 (3회 독립 실행 평균) | Fisher-R1-14B | GPT-5.4 | DeepSeek V4 Pro | 비고 |
| --- | ---: | ---: | ---: | --- |
| **P-Hard Strict pass@1** ($p$값 양측 $z$점수 0.5 이내 + 결론 일치) | **33.0%** | 30.5% | 26.3% | DeepSeek V4 Pro 대비 단일 시도 평균 상대 21%(최대 26%) 개선 |
| **P-Hard Raw pass@1** (기각 방향만 일치) | — | 58.3% | — | 결론 문장만 맞는 비율과 수치 근거까지 맞는 비율의 큰 격차 확인 |

## 단일 검정과 공개물의 경계, 그리고 다메카솔의 해석

![실행·가정·근거·결론·인간 검토의 다섯 관문 앞에서 범위를 설명하는 카솔](./page-04.webp)

이 결과를 읽을 때는 분명한 경계를 남겨 두어야 합니다. 우선 `P-Bench`는 과제마다 단일 가설검정만 다루므로 다중비교 보정이나 상호 의존적인 분석 파이프라인, 혹은 “어떤 단일 검정도 충분하지 않다”는 메타 판단까지는 평가하지 못합니다. 또한 통계 에이전트가 부실한 주장에 그럴듯한 수치 정당성을 입힐 위험이 있어 인간 통계 검토의 대체물로 써서는 안 되며, 논문은 `Fisher-R1`을 `open-weight`로 소개하고 있으나 2026년 8월 10일 확인한 공식 GitHub 저장소(커밋 `99fb1b54ba295e0f56fd5f4c052536697bea2a77`)에는 `README.md` 한 파일만 있고 가중치와 데이터·코드는 아직 올라오지 않았습니다.

데이터 분석 에이전트를 실제 업무 파이프라인에 넣는다면 “분석 완료”를 단일 상태로 두지 않고 다음 다섯 개의 검증 게이트로 나누어야 합니다.

1. **실행**: 데이터 로드와 분석 코드가 에러 없이 끝까지 실행됐는가?
2. **가정**: 선택한 통계 방법이 데이터의 분포·이상치·관측 구조에 부합하는가?
3. **근거**: 보고한 $p$값과 검정 통계량이 실제 실행 로그와 연결되는가?
4. **결론**: 귀무가설 기각 여부가 산출된 수치 근거와 일관적인가?
5. **검토**: 사람이 방법 선택의 타당성과 해석의 한계를 최종 확인했는가?
