AI가 분석 코드를 끝까지 실행하고 “귀무가설을 기각한다”는 답을 냈습니다. 그런데 같은 과제에서 결론 방향만 맞춘 비율과 기준 분석에 가까운 p값까지 낸 비율은 크게 달랐습니다. P-Bench의 어려운 과제에서 GPT-5.4는 Raw pass@1 58.3, Strict pass@1 30.5로 보고됐습니다. 코드를 실행한 사실과 통계적으로 타당한 결론을 낸 사실은 같은 증거가 아니었습니다.

2026년 8월 10일 arXiv 최근 목록에 공개된 preprint **Fisher-R1: Training LLM Agents for Reliable Hypothesis Testing**는 이 간격을 직접 평가합니다. 연구진은 실제 과학 데이터로 만든 P-Bench와, 합성 가설검정 과제로 학습한 Fisher-R1을 제안했습니다. 핵심은 정답 문장만 보는 것이 아니라 어떤 방법을 골라 실행했고, p값과 결론이 기준 분석에 맞는지까지 확인하는 것입니다.

글·해설: 다메카솔

## 코드는 돌아갔지만 검정은 틀릴 수 있다

![불규칙한 데이터가 실행 기계를 통과한 뒤 잘못된 결론 저울로 향하는 장면](./page-01.webp)

논문의 연구 질문은 “AI가 통계 코드를 실행할 수 있는가”보다 좁고 어렵습니다. 데이터와 과학 질문만 받은 에이전트가 적절한 방법을 선택하고, 실제로 분석을 실행한 뒤, p값과 귀무가설 기각 여부를 타당하게 보고할 수 있는지를 묻습니다.

저자들이 제시한 예에서는 에이전트가 데이터의 이상치를 알아차리고도 선형 회귀를 고수합니다. 코드는 정상 실행되고 매우 작은 p값이 나오지만, 이상치의 영향을 줄이는 순위 기반 검정에서는 같은 결론이 나오지 않습니다. 실행 오류가 아니라 추론 방법 선택의 오류입니다.

이 구분은 통계 에이전트뿐 아니라 일반 데이터 분석 자동화에도 중요합니다. 파일을 읽었는지, 코드가 예외 없이 끝났는지, 표가 생성됐는지만 확인하면 가장 중요한 질문이 남습니다. 그 방법이 이 데이터의 분포·관측 구조·가정을 견디는가입니다.

## P-Bench는 질문·실행·판정을 따로 검사한다

![질문과 데이터, 실행 작업장, 숨겨진 기준 판정을 세 구역으로 나눈 증거 경로](./page-02.webp)

P-Bench는 경제학·생물학·의학의 실제 데이터에 기반한 개방형 가설검정 과제 425개로 구성됩니다. Easy 203개와 Hard 222개로 나뉘고, 17개 통계 방법 범주를 포함합니다. 한 범주가 전체의 19%를 넘지 않도록 해 한 가지 익숙한 검정만 반복해서는 높은 점수를 얻기 어렵게 했습니다.

각 과제에서 에이전트는 과학 질문, 데이터 설명, CSV 데이터를 받습니다. 정답 방법은 주어지지 않습니다. 에이전트는 R 환경에서 데이터를 살펴보고 코드를 반복 실행한 뒤 다음 세 가지를 반환합니다.

1. 선택한 통계 방법
2. 계산한 p값
3. 귀무가설을 기각하는지 여부

숨겨진 정답은 논문 문장에서 숫자를 베낀 것이 아닙니다. 저자들에 따르면 기준 분석 코드를 깨끗한 환경에서 다시 실행한 로그에 연결하고, 통계·생물통계 전문가가 요청·데이터·정답의 정합성을 독립 감사했습니다. 재현되지 않거나 모호한 과제는 고치거나 제외했습니다.

평가도 두 층입니다. `Raw`는 기각·기각하지 않음의 방향이 맞는지 봅니다. `Strict`는 그 결론에 더해 보고한 p값이 기준 분석과 양측 z점수 기준 0.5 이내인지 확인합니다. 결론만 우연히 맞고 수치 근거가 다른 경우를 분리하려는 장치입니다.

## Fisher-R1은 실행 흔적과 결과를 함께 학습한다

![검증된 분석 흔적이 품질 체를 거쳐 반복 학습과 두 보상 신호로 이어지는 장면](./page-03.webp)

Fisher-R1은 Qwen2.5-Coder 7B와 14B 백본을 사용합니다. 먼저 합성 통계 과제에서 전문가 모델이 만든 분석 궤적을 품질 필터로 거른 뒤 지도 미세조정합니다. 생성한 4,611개 궤적 중 3,851개, 약 83.5%를 유지했습니다. 이후 8,642개 합성 과제에서 실행 가능한 코드·p값의 기준 근접성·결론의 일관성을 보상으로 강화학습했습니다.

P-Hard Strict pass@1에서 Fisher-R1-14B는 33.0, GPT-5.4는 30.5, DeepSeek V4 Pro는 26.3으로 보고됐습니다. 모두 같은 P-Bench 설정에서 세 번 독립 실행한 평균입니다. 초록은 Fisher-R1-14B가 DeepSeek V4 Pro보다 단일 시도 성공률에서 평균 상대 21% 개선했고, 가장 어려운 과제에서 최대 26% 개선했다고 요약합니다.

이 수치를 “통계에서 항상 더 낫다”로 넓히면 안 됩니다. 평가 과제, 기준 분석, R 환경, 비교 모델 버전과 실행 설정에 묶인 결과입니다. 특히 Raw와 Strict 사이의 간격은 결론 문장만 맞는 것보다 수치 근거까지 맞추는 일이 더 어렵다는 점을 보여 줍니다.

## 단일 검정과 공개물의 경계를 남겨야 한다

![실행·가정·근거·결론·인간 검토의 다섯 관문 앞에서 범위를 설명하는 카솔](./page-04.webp)

저자들은 P-Bench가 현재 과제마다 단일 가설검정만 평가한다고 밝힙니다. 여러 가설을 동시에 탐색할 때 필요한 다중비교 보정, 서로 의존하는 분석 파이프라인, “어떤 단일 검정도 충분하지 않다”는 판단은 후속 과제입니다.

또한 통계 에이전트가 약한 주장에 그럴듯한 정당성을 더할 위험도 명시합니다. 연구진은 P-Bench와 Fisher-R1을 인간 통계 검토의 대체물이 아니라 평가와 감독을 위한 도구로 설명합니다. 의료·정책처럼 해석 오류의 비용이 큰 영역에서는 특히 이 경계를 지켜야 합니다.

재현성에도 현재 한계가 있습니다. 논문은 Fisher-R1을 `open-weight`라고 부르고 공식 GitHub 링크를 제공합니다. 하지만 2026년 8월 10일 확인한 커밋 `99fb1b54ba295e0f56fd5f4c052536697bea2a77`에는 `README.md` 한 파일만 있었습니다. 모델 가중치, P-Bench 데이터, 학습·평가 코드, 라이선스, 릴리스는 확인되지 않았습니다. 따라서 현재 공개물만으로 전체 실험을 재현하거나 open-weight 모델에 접근할 수 있다고 말하지 않겠습니다.

## 다메카솔의 해석: 통계 에이전트에는 다섯 게이트가 필요하다

제가 이 논문을 제품 평가 규칙으로 옮긴다면 “분석 완료”를 한 칸으로 두지 않겠습니다.

- 실행: 데이터와 코드가 실제로 끝까지 실행됐는가?
- 가정: 선택한 방법이 분포와 관측 구조에 맞는가?
- 근거: 보고한 p값이 실행 결과와 기준 분석에 연결되는가?
- 결론: 기각 여부가 그 p값과 일관적인가?
- 검토: 사람이 방법 선택과 해석의 한계를 확인했는가?

이 다섯 층은 논문의 실험 결과를 소프트웨어 운영에 옮긴 다메카솔의 해석입니다. 논문이 모든 데이터 분석 제품에서 이 게이트를 직접 검증한 것은 아닙니다. 다만 실행 성공과 추론 타당성을 합치지 말아야 한다는 근거는 분명합니다.
