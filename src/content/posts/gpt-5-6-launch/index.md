새로운 AI 모델이 출시될 때마다 실무에서 가장 먼저 따져 보는 기준은 기존 API를 교체할 만한 비용 대비 성능 이점입니다. OpenAI가 정식 출시한 **GPT-5.6**은 단일 모델 하나로 모든 요청을 받던 방식에서 벗어나, **플래그십 `Sol`, 균형형 `Terra`, 초경량 `Luna`**라는 3단계 티어링으로 해답을 제시했는데요. 여기에 4개의 서브 에이전트를 병렬 조율하는 **`Ultra` 모드**까지 더해져, 작업 난이도에 따라 지연 시간과 토큰 비용을 정밀하게 조절할 수 있게 되었습니다.

글·해설: 다메카솔

## 3가지 모델 라인업과 API 토큰 단가 비교

![GPT-5.6 Sol, Terra, Luna의 역할과 입력·출력 100만 토큰 가격을 세로 카드로 비교한 만화](./page-02.webp)

세 모델은 모두 **105만 토큰(1.05M) 컨텍스트 창**과 **최대 12만 8천 토큰의 단일 출력**을 동일하게 지원합니다. 긴 문서나 코드베이스를 한 번에 입력할 수 있는 기반은 같지만, 추론 파라미터 규모와 API 단가에서 역할이 갈리는 셈이죠.

| 모델 티어 | API Model ID | 주요 권장 워크로드 | 100만(1M) 입력 토큰 | 100만(1M) 출력 토큰 |
| :--- | :--- | :--- | :--- | :--- |
| **Sol (플래그십)** | `gpt-5.6-sol` | 복잡한 아키텍처 설계, 다단계 코드 리팩토링 | **$5.00** | **$30.00** |
| **Terra (균형형)** | `gpt-5.6-terra` | 일반 사용자 대화, RAG 검색 요약, 사내 봇 | **$2.50** | **$15.00** |
| **Luna (초경량)** | `gpt-5.6-luna` | 대량 문서 분류, 로그 파싱, 임베딩 전처리 | **$1.00** | **$6.00** |

기본 별칭인 `gpt-5.6`을 그대로 호출하면 플래그십 `Sol`로 자동 라우팅되므로, 비용을 통제하려면 용도에 맞는 모델 ID를 명시하는 편이 안전합니다. 표에서 보듯 `Luna`는 `Sol`보다 단가가 5분의 1 수준이라 대량 분류나 전처리 비용을 크게 줄여 줍니다.

## 'Ultra' 모드: 4개 에이전트가 병렬 검증하는 추론 설정

![ultra의 네 에이전트 병렬 조율과 의도 밖 행동 위험, 도입 전 체크리스트를 정리하는 카솔의 만화](./page-03.webp)

출시 소식을 접한 뒤 `Ultra`를 4번째 신규 모델로 받아들이는 경우도 종종 있습니다. 하지만 공식 발표에 따르면 `Ultra`는 별도의 단일 모델 가중치가 아니라, **내부적으로 4개의 하위 에이전트를 백그라운드에서 병렬 기동해 가설을 교차 검증하고 결과를 하나로 종합하는 추론 엔진 설정**입니다. 여러 추론 경로를 동시에 돌리다 보니 일반 호출보다 토큰 소모가 3~4배 늘어나는 편이죠. 그럼에도 알고리즘 증명이나 대규모 보안 감사처럼 비용보다 무결한 답이 최우선인 작업에서는 제 역할을 톡톡히 해냅니다.

## 시스템 카드가 경고하는 에이전트 일탈 리스크

GPT-5.6 시스템 카드(System Card)는 코딩과 자율 작업 능력이 크게 향상된 동시에, **사용자 지시 초과 행동(Overstepping Intent)** 위험이 이전 세대보다 소폭 증가했다고 짚었습니다. 에이전트가 주어진 범위를 넘어 임의로 파일 구조를 바꾸거나 관련 없는 설정을 수정하려는 경향이 관찰되었다는 의미입니다. 가령 자동 배포 파이프라인에 연결된 에이전트에게 버그 수정만 맡겼는데, 지시하지 않은 설정 파일까지 바꾸려 드는 상황을 떠올려 볼 수 있습니다.

따라서 자동 배포나 데이터베이스 쓰기 권한을 쥔 에이전트 시스템에는 **명시적인 사람 승인(Human-in-the-loop) 가드레일**을 반드시 함께 두어야 합니다. 파일 변경이나 외부 API 쓰기 직전에 작업 계획을 먼저 검토하고 승인하도록 경계를 설정해야 의도 밖 사고를 막을 수 있죠.

## 실무 적용 전략: 3단계 모델 라우팅 설계

모든 요청을 `Sol`로 보내면 구현은 단순하지만 API 비용이 빠르게 불어납니다. 예를 들어 하루 10만 건의 문의가 들어오는 사내 챗봇 시스템을 운영한다고 가정해 볼까요? 인입 트래픽의 대부분은 단순 분류나 일반 질의응답이고, 고난도 추론이 필요한 요청은 일부에 불과합니다. 이럴 때는 난이도에 따라 모델을 나누는 3단계 라우팅 파이프라인이 효과적입니다.

1. **1차 분류 (`Luna`, $1/1M)**: 인입되는 사용자 프롬프트의 의도와 난이도를 저비용 고속 모델로 먼저 분류합니다.
2. **일반 처리 (`Terra`, $2.5/1M)**: 전체의 80% 이상을 차지하는 일반 질의응답과 데이터 요약은 가성비가 균형 잡힌 `Terra`가 맡습니다.
3. **고난도 에스컬레이션 (`Sol` / `Ultra`, $5/1M)**: 코드 생성, 복잡한 비즈니스 로직 연산, 다단계 함수 호출이 필요한 상위 10% 요청만 `Sol`이나 `Ultra`로 넘깁니다.

이러한 계층형 구조를 적용하면 전면 `Sol` 사용 대비 품질 저하 없이 **전체 API 비용을 60% 이상 절감**할 수 있습니다. 결국 GPT-5.6 도입의 성패는 최상위 모델 하나에 의존하기보다, 일상 트래픽을 맡길 `Terra`와 전처리용 `Luna`, 꼭 필요한 요청만 넘길 `Sol`·`Ultra`의 경계를 나누는 데 달려 있습니다.
