음성 AI와 대화하다 잠깐 생각하느라 말을 멈췄을 때 AI가 성급히 끼어들거나, 검색 결과를 기다리느라 대화가 뚝 끊기면 몰입이 금세 깨지죠. OpenAI가 2026년 8월 3일 공개한 실시간 음성 시스템 **GPT-Live**의 구현 구조는 바로 이 문제를 **오디오 경로와 검색·깊은 추론·도구 호출을 맡는 비동기 경로의 분리**로 풀었습니다. 7월부터 ChatGPT Voice에 순차 적용 중인 이 구조가 지연의 경계를 어떻게 나눴는지 살펴볼까요?

글·해설: 다메카솔

## 핵심 내용

- **별도 턴 감지기 제거와 전이중 처리**: 음성 모델이 짧은 간격마다 듣기·말하기·기다리기·끼어들기·도구 호출을 직접 판단합니다.
- **전용 미디어와 비동기 RPC 분리**: 오디오는 독립 경로로 흐르고, 검색·추론·도구 호출·저장은 비동기 RPC 경계 뒤로 넘깁니다.
- **무중단 교체와 연결·런타임 개선**: 긴 세션 전환은 백그라운드 워밍업으로 처리하고, WARP(6→1회 왕복)와 Go 이관으로 지연을 줄였습니다(OpenAI 보고 기준).

## 턴이 끝나기를 기다리지 않습니다

![멈춤 감지 뒤 응답하던 이전 흐름과 듣기·말하기를 함께 처리하는 연속 흐름을 비교한 만화](./page-01.webp)

기존 음성 AI 파이프라인은 별도 턴 감지기가 발화 종료를 판정한 뒤에야 메인 모델을 호출하곤 했습니다. 감지기가 너무 예민하면 말을 끊고, 늦게 반응하면 대답이 굼떠지는 딜레마가 있었죠.

예를 들어 사용자가 "내일 서울 날씨 어때… 아, 우산도 챙겨야 하나?"처럼 잠깐 숨을 고르며 말을 잇는 상황을 떠올려 볼 수 있습니다. GPT-Live는 앞단의 별도 감지기를 없애고 모델이 듣기와 말하기를 동시에 처리하는 전이중(full-duplex) 구조를 택했습니다. 짧은 간격마다 행동을 직접 고르기 때문에 생각하는 멈춤과 발화 종료를 훨씬 자연스럽게 구분합니다.

## 오디오와 깊은 작업은 다른 길로 갑니다

![오디오는 중앙 실시간 경로로 흐르고 검색·추론·도구 호출은 옆 비동기 경로에서 처리되는 구조를 보여 주는 만화](./page-02.webp)

가령 대화 도중 최신 정보를 웹에서 찾거나 복잡한 분석을 요청했다고 가정해 봅시다. 오디오 스트림까지 이 작업이 끝나길 기다리면 대화 리듬이 무너지거든요. OpenAI는 시간 민감도에 따라 시스템을 세 경로로 나눕니다.

| 경로 구분 | 담당 작업 | 지연 격리 및 최적화 방식 |
| --- | --- | --- |
| **전용 미디어 경로** | 실시간 오디오 입출력, 음성 모델 반응 | 외부 작업과 격리해 독립 실행, Python `asyncio`에서 Go로 이관해 p95 프레임 전달 성능을 기존 p50 수준으로 단축(내부 측정) |
| **비동기 RPC 경로** | 웹 검색, 프런티어 모델 추론, 도구 호출, 저장 | 세션 시작 시 프런티어 세션과 도구를 미리 열고, 연속 요청에 세션 친화성·프롬프트 캐싱 적용 |
| **백그라운드 상태 경로** | 인스턴스 교대, 대화 문맥 압축 | 기존 인스턴스가 발화를 잇는 동안 새 인스턴스를 데우고 문맥을 채운 뒤 무중단 전환 |

덕분에 도구 호출 하나가 늦어지더라도 결과만 뒤늦게 합류할 뿐, 사용자가 듣는 음성 흐름은 매끄럽게 이어집니다.

## 긴 대화의 무중단 교체와 연결 프로토콜

![기존 모델 인스턴스가 대화를 이어 가는 동안 새 인스턴스가 문맥을 준비하고 카솔이 교대 원칙을 설명하는 만화](./page-03.webp)

음성 세션이 길어질수록 문맥은 계속 불어납니다. 인스턴스 교체나 문맥 압축 때마다 대화가 멈추면 몰입이 깨질 텐데요. GPT-Live는 기존 인스턴스가 말하는 동안 뒤에서 새 인스턴스를 미리 준비해 문맥을 채운 뒤, 완료 시점에 조용히 갈아탑니다.

초기 연결 지연에는 **WARP(WebRTC Abridged Roundtrip Protocol)** 제안도 들어갔습니다. OpenAI는 이 방식으로 WebRTC 미디어·데이터 시작에 필요한 네트워크 왕복(roundtrip)을 6회에서 1회로 줄였다고 설명했습니다.

## Shadow 경로 검증과 공개 범위의 경계

OpenAI는 6개월간의 재설계 결과를 정식 배포하기 전, 기존 Voice가 응답하는 동안 새 시스템을 읽기 전용 shadow 경로로 함께 돌려 검증했습니다. 여기서 GPU 처리량만 봐서는 놓치기 쉬운 지원 컴포넌트 포화, 리전별 지연, 장기 세션 메모리 누수·복구 문제를 미리 찾았다고 밝혔죠.

성능 수치와 제공 범위에는 몇 가지 경계도 함께 확인해 둘 필요가 있습니다. Go 이관 후 p95 프레임 전달 성능이 기존 p50과 맞았다는 보고는 절대 지연값과 표본 크기가 공개되지 않은 내부 관측치입니다.

또한 WARP는 2026년 8월 4일 기준 IETF Internet-Draft 단계라 최종 표준 확정 여부가 아직 열려 있습니다. ChatGPT Voice 적용 역시 순차 진행 중이며, 함께 언급된 GPT-Live API는 출시 일정이 정해지지 않은 예정 상태입니다.

## 다메카솔의 해석

이번 구조의 핵심은 더 빠른 단일 모델보다 **실시간 임계 경로(critical path)를 좁게 유지한 분리 설계**입니다. 체감 지연에 직결되는 오디오는 작고 예측 가능한 경로에 두고, 무거운 검색·추론·도구·저장은 비동기 경로로 격리한 셈이죠.

음성 에이전트를 설계할 때도 "모든 일을 어떻게 빨리 끝낼까"보다 **"무엇이 늦어져도 대화는 이어지게 둘 것인가"**를 먼저 나누어야 합니다. 미디어 프레임, 비동기 도구 합류, 백그라운드 상태 전환을 가르는 기준은 여러 실시간 AI 시스템에 바로 응용할 수 있습니다.
