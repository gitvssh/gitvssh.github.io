AI 에이전트를 강화학습으로 훈련할 때 가중치는 매 스텝 갱신하면서도, 주변에서 문맥과 안내를 구성하는 하네스(harness)는 고정 코드로 두기 쉽습니다. 하지만 모델이 성장할수록 예전 실수는 줄고 새 병목이 나타나는데, 이를 과제와 토큰 예산마다 손으로 맞추기는 어렵거든요. **ModHarness-RL**은 모델과 도구 사이에서 문맥과 안내를 구성하는 하네스를 실행 데이터에서 배우고 훈련과 함께 진화하는 프로그램으로 바꿨습니다.

글·해설: 다메카솔

## 기록 정리와 개입을 두 프로그램으로 나눕니다

기존 방식은 도구를 부를 때마다 대화를 한 줄로 이어 붙여 프롬프트에 쌓습니다. 실행이 길어질수록 불필요한 출력이 단서를 가리고 반복 실수를 막기도 어려워지죠. ModHarness-RL은 턴마다 추론, 도구 호출, 결과, 직전 안내를 구조화된 상태(`State`)로 저장한 뒤 두 파이썬 프로그램을 따로 둡니다.

![고정된 기록 정리 장치와 조절되는 개입 장치를 비교하는 카솔](./page-01.webp)

- **Compression(기록 정리)**: 오래된 턴의 긴 출력을 요약해 예산에 맞추되 원본 상태(`State`)는 보존합니다. 훈련 전 학습한 뒤 본 훈련 내내 **고정**합니다.
- **Steering(행동 개입)**: 반복 실패 패턴을 감지하면 짧은 교정 안내를 붙이는 조건식입니다. 가중치가 바뀌면 실수도 달라지므로 훈련 중 계속 **갱신**합니다.

두 장치는 별도 모델 호출 없이 코드로 실행되어 턴당 지연이 1ms 안팎에 그칩니다. 훈련 중 `Compression`을 열 스텝마다 재학습한 실험에서는 입력 형식이 흔들리며 모든 CodeSearch 설정의 점수가 떨어졌습니다. 결국 압축 규칙은 훈련 전에 고정하고 Steering만 훈련 중에 갱신하는 셈입니다.

예를 들어 `cantools` 과제에서 파이썬 파일 전체를 읽자, `Compression`은 검색 결과와 짧은 조회, 최신 턴을 남긴 채 천 자 넘는 오래된 읽기만 `import`와 선언부 위주로 추려 출력을 5,626자에서 2,809자로 줄였습니다. 반면 `pypika` 과제에서는 `grep` 결과 한 줄만 보고 멈추려 하자, 정의가 하나 이하일 때 켜지는 `Steering` 트리거가 주변 메서드를 확인하라고 안내해 `rlike` 메서드를 맞혔거든요.

## 후보는 실행·리플레이·게이트를 거쳐 채택합니다

실패 기록에서 뽑은 후보를 검증 없이 넣으면 필요한 단서를 지우거나 모델이 곧 고칠 실수까지 건드려 방해가 됩니다. ModHarness-RL은 네 단계로 후보를 가려냅니다.

1. **실행 검증**: `GPT-5-mini`가 최근 궤적을 읽고 후보를 작성하면, 제한된 환경에서 컴파일과 정보 손실 여부를 검사합니다.
2. **리플레이**: `Steering` 후보는 모델 호출 없이 과거 모든 훈련 스텝 궤적에 다시 돌려 실패 추세를 잽니다.
3. **개입 판정**: 하락세인 실패는 RL에 맡겨 보류하고(`continue`), 모호하면 지켜보며(`monitor`), 줄지 않는 실패만 넘깁니다(`intervene`).
4. **검증 게이트**: 후보는 따로 떼어 둔 검증 과제(`held-out`)에서 기존 규칙과 합쳐 실행해 점수가 오를 때만 교체됩니다.

이처럼 모든 후보는 제한된 실행 검사와 리플레이, 그리고 held-out 검증 게이트를 거쳐 채택됩니다.

## CodeSearch 결과와 점수 해석 범위

주 실험인 CodeSearch는 수정할 파일·모듈·엔티티 이름을 맞히는 평가로, 버그 수정 성공률(`resolved rate`)과는 다릅니다. 여덟 장의 GPU에서 동일하게 GRPO 훈련을 마친 최종 체크포인트로 SWE-Bench 세 집합을 검증했습니다.

| 모델 · 예산 | 방식 | Lite / Verified / Pro | 전체 F1 (대비) |
| --- | --- | --- | ---: |
| Qwen3-8B · 제한 | 기본 하네스 | 0.363 / 0.357 / 0.272 | 0.333 (기준) |
| Qwen3-8B · 제한 | + Compression | 0.392 / 0.356 / 0.323 | 0.359 (+8%) |
| Qwen3-8B · 제한 | + Steering | 0.453 / 0.397 / 0.298 | 0.386 (+16%) |
| Qwen3-8B · 제한 | **ModHarness-RL** | **0.441 / 0.437 / 0.351** | **0.412 (+24%)** |
| Qwen3-8B · 충분 | 기본 / ModHarness-RL | — | 0.403 / **0.460** (+14%) |
| Qwen3-4B · 제한 / 충분 | 기본 → ModHarness-RL | — | 0.303→0.368 / 0.361→0.424 |

문맥 제한 조건의 Qwen3-8B 모델에서는 기본 하네스의 CodeSearch 종합 점수가 0.333에 그쳤지만, ModHarness-RL을 쓰면 0.412까지 약 사분의 일 가까이 올라섭니다.

메모리·스킬·프롬프트·하네스 진화 기법(EvolveR, SkillRL, INSPO, HarnessForge)과 고정 하네스(DeepAgents)까지 제치고 네 조합에서 최고 점수를 냈죠. 문맥이 넉넉할 때는 `Compression`이 마지막 호출 프롬프트 토큰을 CodeSearch에서 10%, ALFWorld에서 74% 줄였습니다.

- **실험 설정**: 제한 1,024·충분 8,192토큰이며, SWE-Smith 200스텝 훈련 후 Lite 100·Verified 100·Pro 88(총 288개) 과제를 평가했습니다.
- **교사 대비 및 캐시**: `GPT-5-mini` 제로샷(제한 0.094·충분 0.366)을 웃돌고, 캐시 재사용률 58~72%를 지키며 프리필 토큰을 네 조건 중 세 곳에서 최대 35% 절감했습니다.

## 다른 과제 확장과 연구가 남긴 한계

ALFWorld와 BIRD SQL에서도 각 모듈을 기본 하네스에 얹어 여덟 설정 중 일곱 곳에서 점수를 높였습니다. 다만 실전에 옮길 때는 전체 비교 범위와 작은 검증 게이트, 명시적 규칙의 한계를 함께 살펴야 합니다.

- **비교 범위**: 전체 결합과 외부 비교는 CodeSearch에만 집중됐고, ALFWorld·BIRD SQL은 개별 모듈 확장에 그쳤습니다.
- **작은 게이트와 생성기**: held-out 게이트 표본이 작아 간혹 나쁜 규칙이 통과할 수 있으며, 코드 생성은 상용 `GPT-5-mini`에 의존했습니다.
- **명시적 규칙의 한계**: 구조화된 코드로 검사하므로 도구 호출 패턴에는 강하지만, 자유 대화처럼 의미적 뉘앙스가 핵심인 과제에는 한계가 있습니다.

## 다메카솔의 해석: 기록 정리와 행동 개입은 따로 평가하기

시스템 프롬프트에 로그 축약과 행동 규칙을 섞으면, 점수가 떨어져도 단서가 잘린 탓인지 안내가 판단을 흐린 탓인지 가리기 어렵습니다. 가령 사내 코드 탐색 에이전트를 고친다면 원본 로그는 보존한 채 읽기 요약부터 따로 재보고, 반복되는 실수에만 짧은 개입을 하나씩 붙이는 편이 안전하죠.

이 관점은 [실행 지식을 보존하는 ReproBridge](/posts/reprobridge-execution-knowledge/) 글과도 이어집니다. 앞선 글이 다음 실행자를 위해 코드·환경·실행기를 남겼다면, 이번 연구는 기록 정리와 행동 개입을 별도 변경으로 평가해야 개선 폭을 안전하게 잴 수 있음을 보여 줍니다.
