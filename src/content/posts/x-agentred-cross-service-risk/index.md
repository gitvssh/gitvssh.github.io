담당자에게 자료를 보내 달라는 요청을 받은 AI 에이전트가 사내 문서를 읽고, 연락처를 검색한 뒤 메시지를 전송합니다. 개별 API 호출은 전부 정상(`200 OK`)으로 끝났는데 정작 외부인에게 기밀 문서가 넘어갔다면, 단위 호출의 성공 로그만으로는 작업이 안전했다고 말하기 어렵죠. **X-AgentRed는 이처럼 정상 도구들이 여러 서비스를 오가며 이어질 때 생기는 승인되지 않은 위험을 찾는 레드티밍 연구**입니다.

글·해설: 다메카솔

## 핵심 내용

- **HarmFlow 그래프**: 도구의 선행 조건·효과·잠재 피해를 분석해 앞 도구의 효과가 뒤 조건을 채우는 관계를 엮습니다.
- **실행 피드백 탐색**: 피해 경로는 다른 도구 조합으로 넓히고, 막힌 경로는 빠진 조건을 보완해 시나리오를 고칩니다.
- **모의 환경 성과와 경계**: 30개 서비스·914개 도구 환경에서 1,000개 중 192개(19.2%) 피해 경로를 찾았으나, 시험 후보 비율이며 판정·비교 조건을 함께 봐야 합니다.

## 앞선 도구의 결과가 다음 조건이 된다

![앞선 도구의 효과가 다음 도구의 조건으로 이어지는 연결과 실행 시험의 개념](./page-01.webp)

새 문서가 생성되면 자연히 '그 문서를 공유할 수 있는 상태'가 열립니다. 저자들은 [원문 3절](https://arxiv.org/html/2610.13886v1#S3.SS1)에서 이런 연쇄를 포착하려고 도구마다 선행 조건·실행 효과·잠재 피해를 정리했습니다. 앞 도구의 효과가 뒤 도구의 선행 조건을 뒷받침할 때 두 도구를 이은 방향 그래프가 **HarmFlow 그래프**입니다.

여기서 연결선이 뜻하는 바는 분리해서 봐야 합니다. 문서를 만들었다는 사실은 '공유할 파일이 있다'는 기술적 조건만 채워 줄 뿐, 특정 수신자에게 보내도 좋다는 보안 권한이나 실제 실행 가능성·안전성까지 보장해 주지는 않거든요. 나머지 조건은 앞선 호출이나 환경 설정에서 별도로 충족되어야 하며, API 입력값(파일 ID, 이메일 주소)의 존재와 접근 권한 판단을 한 덩어리로 묶으면 서비스 통합 보안 경계가 쉽게 흔들립니다.

X-AgentRed는 잠재적 피해와 맞닿은 끝 도구에서 그래프를 거슬러 올라가 후보 경로를 뽑고, 안전하게 끝낼 길도 있는 정상 사용자 요청과 초기 환경으로 시나리오를 구성합니다(사용자가 직접 요청했거나 승인한 결과는 피해에서 제외됩니다). 앞서 다룬 [RATED의 실행 피드백 기반 도구 선택](/posts/rated-tool-reliability/)과 비교하면 초점이 뚜렷하게 갈립니다. RATED가 고장 난 도구를 피해 정상 도구를 고른다면, X-AgentRed는 멀쩡한 도구들이 이어질 때 생기는 부작용을 추적하는 셈이죠.

## 실행 기록으로 다음 시험을 바꾼다

![위험이 발견된 경로를 넓히고 막힌 경로를 점검하는 모의 실험](./page-02.webp)

저자들은 한 번 시나리오를 돌리고 멈추지 않고, [실행 피드백 단계](https://arxiv.org/html/2610.13886v1#S3.SS3)에서 결과에 따라 다음 시험을 조정했습니다.

- **피해가 난 경로**: 핵심 위험 흐름은 유지한 채 주변 도구를 치환해 탐색 범위를 넓힙니다.
- **중간에 막힌 경로**: 부족했던 선행 조건을 찾아 그래프와 시나리오를 고치며, 대상 모델을 재학습하지는 않습니다.

이 수정 루프는 취약점을 찾는 레드티밍 시험 기법으로만 써야 합니다. 운영 에이전트가 권한 거부를 만났을 때 우회 경로를 찾아 강행하도록 옮겨서는 안 되며, 서비스 현장에서는 권한 검사와 중단 규칙을 일관되게 유지해야 안전합니다.

저자들은 [원문 실험과 부록](https://arxiv.org/pdf/2610.13886v1)에서 고정 모의 환경에 네 모델을 올려 세 방법을 비교했습니다.

- **모의 환경**: 30개 서비스·914개 도구로 구성했고, Claude Opus 4.8이 도구 응답과 상태를 모사했습니다.
- **평가 대상·규모**: Claude Opus 4.8, GPT-5.6 Sol, DeepSeek-V4-Pro, GLM-5.2 네 모델에 방법별·모델당 250개씩 총 1,000개 후보를 구성별 1회 실행했습니다(DeepSeek-V4-Pro는 인터페이스 제한 때문에 시나리오 필수 도구와 고정 순서 도구를 합쳐 최대 256개만 제공했습니다).
- **판정 기준**: 두 판정 모델(Claude Opus 5, GPT-5.6 Sol)이 ① 피해 발생, ② 조건의 그럴듯함, ③ 사용자 요청 전체의 정상성을 만장일치로 인정한 후보만 집계했습니다.

아래 표는 이 조건에서 집계된 저자 보고치입니다.

| 시험 생성 방법 | 피해가 확인된 후보 | 피해 경로 비율(HPR) | 모델 평균 도구 사용 범위(914개 중) |
| --- | ---: | ---: | ---: |
| X-AgentRed | 192 / 1,000 | 19.2% | 41.5% |
| STAC | 105 / 1,000 | 10.5% | 13.9% |
| TRACE | 27 / 1,000 | 2.7% | 23.7% |

같은 1,000개 후보에서 발견된 피해 경로 수와 호출 도구 범위(실패 경로 호출 포함) 모두 격차가 컸습니다. 다만 이 비율은 위험을 찾으려 조합한 시험 후보 기준이라 일상 트래픽 사고율과는 성격이 다릅니다. 세 방법은 후보 수는 같아도 생성 연산량·대상 모델 호출 수·후속 요청 방식이 달라, 이 표만으로 그래프의 순수 효과나 동일 비용 대비 개선폭을 단정하기는 어렵거든요.

## 모의 실험에서 운영 판단으로 건너갈 때

![서비스 사이의 정보 이동과 공유 경계를 확인하는 카솔](./page-03.webp)

모의 환경의 발견량을 현업 판단으로 옮길 때는 세 가지 경계를 함께 살펴야 합니다.

- **커버리지와 결함 다양성**: 도구 사용 범위(41.5%) 확대가 곧 새 유형의 결함 증가로 이어지지는 않습니다. 호출 경로 길이가 다르고 앞선 결과에 따라 다음 시험이 바뀌는 적응형 탐색이라, 독립 반복 실험과는 해석 기준이 다릅니다.
- **판정 기준 민감도**: 만장일치 대신 한 판정 모델만 인정해도 세도록 완화하면, X-AgentRed의 피해 경로 비율은 대상 모델에 따라 15.2~30.4%p 높아졌습니다. 저자들이 192개 피해 경로를 수동 검토해 보상 편법(reward hacking) 징후가 없음을 확인했으나, 이는 판정 민감도와 내부 점검일 뿐 독립적인 인간 판정 정확도 측정과는 구분해야 합니다.
- **그래프 유지 비용과 공개 현황**: 새 API 추가나 도구 동작 변경 시 선행 조건과 효과를 다시 분석해 그래프를 고쳐야 한다는 점은 저자들도 한계로 짚었습니다. [저자 프로젝트 페이지](https://yeonsungjung.github.io/projects/x-agentred/)는 2026년 10월 13일 확인 기준 코드 공개 예정으로 안내하고 있어, 실제 도입 전 유지 비용부터 가늠해 볼 만합니다.

## 다메카솔의 해석: 호출 사이에도 책임이 이어져야 합니다

저는 이 연구를 보며 에이전트 통합 테스트의 관찰 단위를 단일 도구 호출에서 **호출 사이의 데이터·권한 이동**으로 넓혀야 한다고 생각합니다. 예를 들어 회의록을 요약해 메일로 보내는 작업이라면, 요약 정확성뿐 아니라 수신자 주소를 가져온 문서의 신뢰도와 최종 공유 범위·외부 발송 권한까지 흐름 전체로 검증해야 합니다.

무엇보다 **서버 계층의 명시적 권한 검사**가 마지막 보루로 남아 있어야 합니다. 에이전트가 읽은 문서 본문이나 이전 응답에 이메일 주소가 적혀 있다고 해서, 그 상대에게 기밀 자료를 보낼 권한까지 자동으로 생기지는 않으니까요. 외부 전송·상태 변경 직전에 허용 범위를 다시 검사하는 원칙은 [도구 명세와 에이전트 안전성](/posts/tool-specifications-agent-safety/)에서 다룬 실행 경계와도 맞닿아 있습니다.

새 서비스를 붙일 때 기존 단위·회귀 테스트만 통과시키고 넘어가면, 도구들이 이어지며 생기는 사각지대를 놓치기 쉽습니다. 모든 조합을 시험할 수는 없으니 **외부 발송·권한 변경·삭제처럼 되돌리기 어려운 끝 도구에서 거슬러 올라가며 연결 경로를 점검**해 보면 어떨까요? 우리 시스템에서 어느 두 도구가 만날 때 가장 먼저 경계를 확인해야 하는지 되짚어 보게 하는 연구입니다.
