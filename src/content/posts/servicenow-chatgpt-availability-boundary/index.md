사내 업무 시스템인 ServiceNow와 ChatGPT가 연결된다는 소식을 접하면, 개발팀은 당장 두 가지부터 따져 보게 됩니다. 지금 바로 붙여 볼 수 있는 기능이 무엇인지, 그리고 연결했을 때 기존 사내 데이터 권한이 그대로 지켜지는지 궁금해지죠. OpenAI가 2026년 10월 28일 발표한 ServiceNow 협력 확대는 현재 제공되는 연결과 미리보기, 향후 출시 계획을 한 자리에 함께 소개하고 있어 경계를 나눠 읽어야 합니다.

글·해설: 다메카솔

## 지금 제공되는 연결과 조직 권한의 경계

2026년 10월 31일 다시 확인한 [OpenAI 공식 발표](https://openai.com/index/openai-servicenow-partnership-expansion/)에 따르면, 현재 제공 단계로 안내된 핵심 구성은 **ServiceNow MCP 플러그인**입니다. OpenAI는 이 플러그인이 OpenAI 마켓플레이스에서 제공된다고 설명합니다. 연동할 때는 고객이 자신의 ServiceNow 인스턴스를 직접 연결한 뒤 외부로 노출할 기능을 고르게 됩니다.

![연결할 기능 선택, 업무 권한 적용, 출시 계획 확인을 구분한 만화](./page-01.webp)

실제 요청이 오갈 때는 ServiceNow의 **Action Fabric**이 기존 업무 규칙과 권한을 적용한다고 OpenAI는 설명합니다. 흔히 사내 업무 시스템을 외부 AI 대화창과 잇는다고 하면, 조직의 모든 기록을 누구나 조회하거나 마음대로 고칠 수 있게 풀리는 상황을 먼저 걱정하기 쉽습니다. 하지만 공식 발표가 제시하는 경계는 일괄 전면 개방과는 거리가 있으며, 조직이 고른 노출 기능 위에서 기존 ServiceNow 권한 체계가 작동하는 구조인 셈이죠.

다만 발표 문구만으로 사내 통제가 자동으로 완결된다고 단정하기는 어렵습니다. 실제 도입을 검토하는 팀이라면 자사 계정의 설치 자격과 연결 조건을 먼저 확인하고, 선택한 노출 기능과 기존 권한이 사내 기준대로 작동하는지 직접 점검하는 편이 안전합니다.

## 현재 제공, 미리보기, 출시 계획을 나눠 읽기

협력 발표에서 또 하나 헷갈리기 쉬운 지점은 **지금 쓸 수 있는 기능**과 **앞으로 나올 계획**이 같은 흐름 안에 나열된다는 점입니다. 공식 발표의 주요 항목을 상태별로 나누면 아래 표와 같습니다.

| 구분 | 공식 발표의 상태 | 도입 검토 시 해석 |
| --- | --- | --- |
| **ServiceNow MCP 플러그인** | OpenAI 마켓플레이스 제공 | 현재 연결 검토 대상 |
| **ChatGPT 안의 대화형 경험** | 미리보기 | 정식 제공 전 시험 단계 |
| **플러그인 기능 강화** | 2026년 말 예상 | 단기 예정 항목 |
| **음성 기능** | 2027년 1분기 예상 | 향후 출시 계획 |
| **보안 기능** | 2027년 1월 조기 접근, 2027년 2분기 일반 제공 계획 | 단계적 출시 예정 |
| **AI Workflow Factory의 Codex** | 2027년 예상 | 중장기 출시 계획 |

표에서 보듯 현재 마켓플레이스 제공으로 안내된 대상은 ServiceNow MCP 플러그인입니다. 반면 ChatGPT 안의 대화형 경험은 미리보기로 소개됐고, 플러그인 기능 강화와 음성·보안·Codex 연동은 모두 출시 예정 시점으로 제시된 회사 계획에 해당하거든요. 출시 예정 시점은 확정된 제공 결과와 다르므로, 지금 착수하는 연동 검토에 향후 계획 항목까지 미리 묶어 두면 일정이 어긋나기 쉽습니다.

## 실무 검토 시나리오와 확인 포인트

예를 들어 사내 업무 워크플로를 ServiceNow로 운영하는 개발팀이 "ChatGPT를 연결하면 대화형 경험과 음성·보안 기능, Codex 연동까지 한 번에 도입할 수 있는지" 검토 요청을 받았다고 가정해 볼까요? 공식 발표의 경계를 그대로 대입하면 과제가 두 단계로 갈립니다. 당장 연결과 권한을 시험해 볼 범위는 마켓플레이스의 ServiceNow MCP 플러그인과 미리보기 성격의 대화형 경험까지로 두고, 음성·보안·Codex 연동은 2027년 출시 일정을 지켜보며 후속 과제로 분리하는 편이 현실적이죠.

실제 적용을 검토할 때는 세 가지 항목을 순서대로 짚어 두면 판단이 수월합니다.

- **기능별 제공 상태 구분**: 팀이 해결하려는 업무가 현재 제공되는 ServiceNow MCP 플러그인 범위인지, 미리보기나 향후 출시 예정 항목에 의존하는지 먼저 분리합니다.
- **계정 자격과 노출 기능 선택**: 조직 계정에서 마켓플레이스 플러그인 설치가 가능한지 확인하고, 자사 ServiceNow 인스턴스에서 필요한 기능만 선택해 노출합니다.
- **기존 업무 규칙과 권한 점검**: Action Fabric이 기존 ServiceNow 업무 규칙과 사용자 권한을 실제 연결 경로에서도 의도대로 적용하는지 사내 기준에 맞춰 확인합니다.

결국 이번 협력 확대 발표를 실무에 옮길 때는 '연동 가능'이라는 제목보다 **제공 단계·노출 범위·기존 권한**이라는 세 갈래 경계를 먼저 긋는 일이 중요합니다. 필요한 기능의 제공 상태와 조직의 연결·권한 설정을 따로 확인해 두면 과도한 기대나 일정 혼선을 줄일 수 있습니다.
